开发页面：`http://100.70.120.234:5173`，通过已有 NetBird 网络访问。现有账号和认证方式沿用；管理员可在用户管理中配置新增固定角色。浏览器 API 走页面同源 `/api`，不能设置成访问者的 localhost。此地址是当前实例的访问地址，恢复新实例时需重新检查 NetBird 地址与服务就绪。

本 HTTP 地址并非浏览器 secure context：业务幂等键使用 getRandomValues，导入身份摘要使用经锁定的 SHA-256 库，避免依赖受限的 randomUUID/subtle。保持平台 HTTPS proxy、CA 验证、网络策略和原 NetBird/SSH 状态。镜像构建通过 BuildKit secret 挂载 CA，运行容器只读挂载 CA 和完整系统根证书 bundle，不把当前会话 CA 留在镜像层中；HTTPS registry 实测返回 200。

## 顶部模块与左侧菜单（2026-10-12 更新）

顶部采用三个业务入口：工单系统、资产管理、备品备件与库存。左侧菜单随当前路由切换：仪表盘/工单列表/新建工单/队列/SLA；资产台账/导入资产；备件目录/库存余额/库存流水/仓库管理。工单仪表盘位于 `/tickets/dashboard`，为有 `ticket:read` 权限的用户提供工单系统默认入口，显示工单指标和状态分布。每个业务模块左侧只显示该模块的功能。顶部右侧的“平台管理”作为独立入口，进入后左侧显示组织管理、用户与权限，并按原权限过滤；不混入业务菜单。头像下拉菜单包含个人设置、安全验证与退出；语言、主题和通知仍在公共顶栏。点击 Logo 返回 `/dashboard`，显示无左侧菜单的整页平台概览（按权限显示业务入口及资产/库存概览），与工单仪表盘分开；个人设置页同样不占用业务侧栏。

## 云开发启动

使用已有 checkout，保留未提交变更，不新建 worktree，不覆盖 .env，不删除命名卷。

```bash
source /workspace/assay-cloud/activate.sh
cd /workspace/assay
python3 /workspace/assay-cloud/prepare-docker.py
docker compose --progress plain -f docker-compose.dev.yml -f /workspace/assay-cloud/compose.cloud.json up -d --build api web
python3 /workspace/assay-cloud/readiness.py
```

API 启动依次冻结安装、Prisma generate、migrate deploy、幂等 seed、watch；web 冻结 Bun 安装并加载同源云 Vite 配置。首次完整启动需按原环境说明启动 PostgreSQL/Redis/RustFS 等基础服务；Compose 会复用已有依赖与卷。只需开发软件更新时不要重启 NetBird。

API `/health` 须为 status=ok、db=up、redis=up、storage=s3、storageStatus=up；网页和登录必须另行验证。仅有 PID、端口或容器运行不能证明业务可用。

执行 host 的 API build 会重写绑定的 dist；应在检查后重启 API 并确认就绪，避免与 live watch 混用造成临时 MODULE_NOT_FOUND。日常无输出编译检查可使用 `pnpm --dir apps/api exec tsc --noEmit`。

## 当前边界及后续

本期备件为整数数量、单 SKU 业务，没有批次/序列化备件、采购、折旧或成本计价；资产/库存权限为公司全局，未实现部门范围隔离。有库存流水的操作人以停用账号保留，库存操作外键阻止硬删除；更改责任人后再处理在用资产关联。履历最近 100 条、单次导入 500 台、导出上限 10000 条业务记录。请假/报销仅预留组织与业务适配/审批协议，没有虚构的运行流程。

可选“只读读取 NetBox”需要在云环境安全配置 `NETBOX_API_TOKEN`，仅指向 `netbox.cloudcele.com`；`NETBOX_API_BASE_URL` 默认 HTTPS 同一域名。已声明配置元数据并由云 Compose 传给 API，未保存令牌值。当前运行实例未配置专用 API token，因此此按钮会明确提示 503，Excel 导入与已完成的 132 台快照导入可正常使用。用户提供的登录凭据只用于一次明确授权的只读查询，没有转换为 PAT，也没有自动同步或外部写入。

环境草稿保存不等于发布快照。发布由用户在环境设置中审阅保存并发布；当前任务的运行、草稿保存、新任务恢复分别验证，尚未验证新任务恢复。代码未推送 GitHub；之后更新 main 前须先保留当前改造，不能 force-reset。
