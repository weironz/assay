# 工单队列使用指南

队列（Queue）是把同一类工单归到同一个**处理团队或责任域**的分流容器。它回答的是“这张工单应该由哪个团队处理”，而不是“具体由谁处理”。

在 IDC 算力租赁场景中，可把队列理解为一线服务台的分诊台：用户建单时选定队列，主管或管理员再将工单指派给该队列中的具体处理人。

## 1. 队列与其他字段的区别

| 字段 | 回答的问题 | 示例 | 当前系统作用 |
| --- | --- | --- | --- |
| 队列 | 哪个团队/责任域负责？ | BKK 网络支持、GPU 硬件支持 | 分流、列表筛选、统计归属 |
| 分类 | 问题属于什么技术领域？ | IB 网络、以太网网络、GPU 卡、B300 | 描述问题主题、便于统计 |
| 类型 | 这是什么服务请求？ | 故障、服务请求、咨询 | 决定响应/解决 SLA 时限 |
| 处理人 | 谁是主责工程师？ | 张三 | 接收指派、处理工单、承担主责 |
| 协作成员 | 谁参与讨论或关注？ | 网络工程师、GPU 专家 | 参与讨论，不改变主责人 |

简言之：**队列管团队，处理人管个人，分类管问题，类型管 SLA。**

## 2. 当前系统中的工作方式

### 2.1 建单时选择队列

在“新建工单”页面的“队列”下拉框中选择对应队列。该项当前为选填；没有明确归属时可以先留空，由服务台后续分诊。

建单后，工单会带上该队列归属，但不会自动指派给某位工程师，状态仍为“新建”。SLA 从建单时刻开始计算；队列不会改变 SLA 时长，SLA 由所选工单类型决定。

### 2.2 处理人分派时调整队列

主管或管理员在工单详情中执行“指派”时，可以同时：

1. 选择主处理人；
2. 必要时改为更合适的队列；
3. 提交后，工单进入“已指派”，处理人收到站内通知。

例如，一张最初进入“服务台”的 BKK 集群网络异常，经确认后可改到“BKK 网络支持”队列，再指派给网络工程师。

### 2.3 在列表中按队列查看

工单列表顶部提供“全部队列”筛选器。选择某个队列后，可集中查看该责任域的待办、处理中、挂起或已完成工单。

这适合主管进行日常排班和容量检查，例如查看“GPU 硬件支持”队列中是否存在长期未分派的高优先级工单。

## 3. 管理队列

进入左侧导航的“队列”页面，可创建、查看和删除队列。

创建时填写：

- **名称**：应使用稳定的团队或责任域名称；
- **描述**：写清受理范围、边界与升级方向，方便建单人选择。

当前只有拥有 `queue:manage` 权限的角色可以管理队列。系统固定角色中，管理员具备此权限；其他人员可以查看队列并在建单时选择。

### 推荐命名

队列应按服务能力或团队划分，避免按个人姓名建立队列。IDC 场景可从以下结构开始：

| 队列 | 典型受理范围 |
| --- | --- |
| 服务台 / 分诊 | 归属暂不明确、需要初步判断的请求 |
| BKK 网络支持 | BKK 机房内 IB 网络、以太网网络、链路与连通性问题 |
| GPU 硬件支持 | GPU 卡、B300、服务器硬件与设备序列号相关问题 |
| 机房设施支持 | 机柜、电力、制冷、现场操作与资产定位问题 |
| 平台与交付支持 | 租户开通、资源交付、平台配置与服务请求 |

名称中保留地域或机房标识（如 `BKK`）很有价值：后续新增其他站点时，可以直接扩展为 `BKK 网络支持`、`SIN 网络支持`，避免责任范围混淆。

## 4. 推荐分流流程

```text
用户建单
  → 选择队列（不确定则选“服务台 / 分诊”）
  → 选择分类与类型
  → 主管确认归属
  → 必要时调整队列，并指派主处理人
  → 需要跨团队时添加协作成员讨论
  → 解决并关闭工单
```

### 示例：BKK 集群 GPU 不可用

1. 用户填写机房 `datazone`、集群 `BKK-CL01`、设备 SN，并将分类选为“GPU 卡”。
2. 队列选择“GPU 硬件支持”；若用户无法判断，可先选择“服务台 / 分诊”。
3. 主管确认是 GPU 侧问题后，将工单分派给主责硬件工程师。
4. 若发现可能涉及 RDMA 通信，主责人可邀请网络工程师作为协作成员；工单主责仍保持唯一，避免 SLA 责任不清。

## 5. 使用注意事项

- **不要把队列当成权限隔离。** 当前权限由系统角色、工单归属和协作关系控制；队列本身不会限制谁能查看或操作工单。
- **不要把队列当成 SLA 规则。** 当前 SLA 由工单类型配置，从建单开始计时；挂起期间暂停计时，恢复后继续。
- **不要把队列当成个人待办。** 个人待办应依赖“处理人”筛选；队列用于团队维度。
- **删除前先清空或迁移工单。** 已有关联工单的队列不能直接安全删除；应先把工单改到其他队列或取消队列归属，以保留历史记录。
- **默认处理人尚未启用自动分派。** 数据模型已预留默认处理人字段，但当前 Web 页面没有配置入口，建单也不会自动把工单指派给该人。需要自动派单时，应作为单独功能实施，并配合值班、兜底与 SLA 升级规则设计。

## 6. 管理员日常检查清单

1. 每周检查是否有长期“新建”且未分派的工单；
2. 每个队列的描述是否仍与实际职责一致；
3. 新增机房、产品或团队时，先确定由现有队列覆盖还是建立新队列；
4. 队列名称保持稳定，组织调整时优先更新描述和分派规则，避免频繁删除重建导致历史统计割裂；
5. 对跨团队问题保持一个主处理人，其余人员通过协作成员参与讨论。
