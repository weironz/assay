# 部署文档

两种部署方式，按需选一种：

| 场景 | 访问方式 | 适用 | compose 文件 |
| --- | --- | --- | --- |
| **场景 1** | `http://服务器IP:8088` | 内网、测试、没有域名 | `docker-compose.yaml` |
| **场景 2** | `https://你的域名` | 生产，自动 HTTPS | 仓库模板 `docker-compose.traefik.yaml`；按 §2.3 安装后为 `docker-compose.yaml` |

两者的数据卷逻辑名不同（`*-prod` vs 无后缀），**不要互相覆盖**；实际 Docker 卷名还包含 Compose 项目名，详见 §6.3。

---

## 0. 前置条件

| 项目 | 要求 |
| --- | --- |
| 操作系统 | 任意支持 Docker 的 Linux |
| Docker | 20.10+，含 compose v2（`docker compose version` 能输出版本） |
| 内存 | 最低 2 GB，推荐 4 GB |
| 磁盘 | 20 GB 起。附件上传期间会占临时盘：**并发数 × 单文件大小**（单文件上限 512 MB） |
| 端口 | 场景 1 需要 8088（可改）；场景 2 需要 80 和 443 |

安装 Docker（如未安装）：

```bash
curl -fsSL https://get.docker.com | sh
systemctl enable --now docker
docker compose version   # 确认输出 v2.x
```

## 1. 场景 1：单机部署，直接 IP 访问

### 1.1 准备目录与配置

```bash
mkdir -p /data/assay && cd /data/assay

# 拉取 compose 与环境变量模板
curl -fsSLO https://raw.githubusercontent.com/weironz/assay/main/docker-compose.yaml
curl -fsSL  https://raw.githubusercontent.com/weironz/assay/main/.env.prod.example -o .env
```

也可以直接 `git clone https://github.com/weironz/assay.git` 后进入目录，
再 `cp .env.prod.example .env`。

### 1.2 填写 .env

用编辑器打开 `.env`，**至少改这 5 项**：

```bash
# 换成服务器的真实 IP 和端口，必须和浏览器地址栏完全一致
PUBLIC_URL=http://192.168.1.10:8088
WEB_PORT=8088

POSTGRES_PASSWORD=<强密码>
S3_ACCESS_KEY=<随机串>
S3_SECRET_KEY=<随机串>
AUTH_SECRET=<长随机串>
ADMIN_PASSWORD=<管理员初始密码>
```

生成随机串：

```bash
openssl rand -base64 32
```

> ⚠️ **`PUBLIC_URL` 是最容易踩的一项。**
> 它同时用作登录会话的签发地址和 CORS 白名单，必须与用户地址栏里的地址
> **逐字一致**（协议、IP/域名、端口都算）。写成 `localhost` 而实际用 IP 访问，
> 症状是「密码明明正确却登不进去」，且控制台报 CORS 错误。

### 1.3 启动

```bash
docker compose pull
docker compose up -d
```

首次启动时 API 容器会自动执行数据库迁移并写入初始数据（权限、角色、管理员、
默认队列、工单类型、分类、机房集群），需要 30 秒左右。

### 1.4 验证

```bash
# 容器是否都起来了
docker compose ps

# 迁移与初始化是否完成
docker compose logs api | grep -E "migration|Seed|已启动"
```

期望看到：

```
All migrations have been successfully applied.
✅ Seed 完成：权限/角色/admin/默认队列/类型/分类/机房集群
API 已启动: http://localhost:3000
```

再验证对外访问：

```bash
curl -I http://192.168.1.10:8088/          # 期望 200
curl -s http://192.168.1.10:8088/api/me    # 期望 {"message":"未登录",...,"statusCode":401}
```

`/api/me` 返回 401 是**正常的**——说明后端通了、只是没带登录态。

### 1.5 登录

浏览器打开 `http://192.168.1.10:8088`，用 `.env` 里的
`ADMIN_EMAIL` / `ADMIN_PASSWORD` 登录，**登录后立刻改密码**。

## 2. 场景 2：Traefik + 域名 + 自动 HTTPS

比场景 1 多两步：先有 Traefik，再把 assay 挂上去。

### 2.1 域名解析

先把域名 A 记录指向服务器公网 IP，并确认解析已生效：

```bash
dig +short tickets.example.com     # 应返回服务器 IP
```

> 解析没生效就启动会导致 Let's Encrypt 签发失败。**Let's Encrypt 对失败次数
> 有限流**，反复重试会被暂时锁住，届时只能干等，所以务必先确认解析再启动。

### 2.2 启动 Traefik（已有 Traefik 可跳过）

```bash
docker network create traefik-network

mkdir -p /data/traefik && cd /data/traefik
curl -fsSLO https://raw.githubusercontent.com/weironz/assay/main/deploy/traefik/docker-compose.yaml
echo "ACME_EMAIL=you@example.com" > .env

docker compose up -d
docker compose logs -f traefik      # 看有没有报错，Ctrl+C 退出
```

**已经有 Traefik 的话**，不用动它，只要确认这三样存在且名字一致，
因为 assay 的标签是按这些名字写的：

| 名称 | 类型 | 用途 |
| --- | --- | --- |
| `traefik-network` | 外部 docker 网络 | Traefik 与 assay-web 通信 |
| `websecure` | entrypoint | HTTPS 入口（:443） |
| `letsencrypt` | certresolver | 证书签发 |

名字不同就改 `docker-compose.traefik.yaml` 里 `web` 服务的 labels。

### 2.3 部署 assay

```bash
mkdir -p /data/assay && cd /data/assay

curl -fsSLO https://raw.githubusercontent.com/weironz/assay/main/docker-compose.traefik.yaml
mv docker-compose.traefik.yaml docker-compose.yaml
curl -fsSL https://raw.githubusercontent.com/weironz/assay/main/.env.prod.example -o .env
```

编辑 `.env`，与场景 1 的区别是**这两项**：

```bash
PUBLIC_URL=https://tickets.example.com     # 注意是 https
PUBLIC_DOMAIN=tickets.example.com          # 不带协议，Traefik 路由用
```

`WEB_PORT` 在这个场景下无效（web 不再对宿主机暴露端口，流量走 Traefik）。
其余密码、密钥项与场景 1 一样必须改。

启动：

```bash
docker compose pull
docker compose up -d
```

### 2.4 验证

```bash
docker compose ps
docker compose logs api | grep -E "migration|Seed|已启动"

curl -I https://tickets.example.com/            # 期望 200
curl -s https://tickets.example.com/api/me      # 期望 401 未登录
```

证书签发需要几十秒。如果暂时是自签证书或 404，先看 Traefik 日志：

```bash
docker logs $(docker ps -qf name=traefik) --tail 50
```

## 3. 邮件（可选）

不配置邮件系统照常可用，只是**邮箱验证和找回密码不可用**。

内网自建、没有发信服务时，建议在 `.env` 里显式关掉邮箱验证，
否则新注册用户收不到验证信、无法登录：

```bash
REQUIRE_EMAIL_VERIFICATION=false
```

需要发信时二选一（详见 `.env.prod.example` 内注释）：阿里云邮件推送
DirectMail，或任意 SMTP 服务。改完执行 `docker compose up -d` 生效。

## 4. 升级

```bash
cd /data/assay
docker compose pull
docker compose up -d
```

数据库迁移在 API 容器启动时自动执行，无需手工操作。

指定版本（推荐生产使用固定版本而非 `latest`）：

```bash
sed -i 's/^IMAGE_TAG=.*/IMAGE_TAG=1.3.2/' .env
docker compose pull && docker compose up -d
```

回滚同理，把 `IMAGE_TAG` 改回旧版本再 `pull && up -d`。

> **注意**：回滚镜像**不会回滚数据库迁移**。跨版本回滚前先确认旧版镜像
> 能兼容当前库结构，必要时从备份恢复。

### 4.1 两步验证与特权账号灰度启用

Phase 2 安全验证部署时保持 `PRIVILEGED_MFA_MODE=optional`（默认值），先让每位管理员、主管绑定并验证 TOTP，离线保存恢复码，并检查敏感操作能用密码和动态码完成。检查还应覆盖用户启用/停用、自助删号的独立 `account` 验证，以及邮件自助/管理员重置密码后目标用户旧会话失效；不能删除、停用最后一位在职管理员或移除其管理员角色。生产部署务必确认 `20260928130000_session_epoch` 已由 `prisma migrate deploy` 安装：它提供数据库会话版本及凭据变更触发器，Redis 会话索引遗漏令牌时仍能拒绝旧会话；`db push` 本身不会安装该触发器。开发模式会在 `db push` 后单独幂等安装安全触发器，不代表迁移历史已完成。全部就绪后再设置 `PRIVILEGED_MFA_MODE=enforce`、重建 API 容器。`enforce` 会限制未绑定的特权账号访问业务接口；已绑定账号在任一模式下执行敏感操作都不能只用密码。若最后一位管理员丢失验证器，单纯改回 `optional` 无法跳过已绑定的第二因子。完整接口、验证清单和人工恢复边界见[两步验证与验证器使用](09-两步验证与验证器使用.md)。

## 5. 备份与恢复

数据在三个卷里：数据库、Redis、附件对象存储。**必须备份的是数据库、附件和认证密钥。** 本脚本不备份 Redis：Better Auth 的 `secondaryStorage` 使用 Redis 存放会话、待验证/重置流程的临时状态及限流计数，队列也依赖 Redis；数据库保存持久的会话版本。恢复数据库备份时必须同时使用空 Redis/清除旧认证会话，避免数据库会话版本回退后旧 Redis 令牌重新有效。恢复到空 Redis 后，用户需重新登录，未完成的验证/重置链接可能需要重新发起，限流窗口计数会清零，未处理队列任务也不会从本备份恢复。Redis 或数据库暂时不可用时，服务端不能验证会话并拒绝认证，不会降级为信任 Cookie。恢复后应主动检查认证、邮件验证和队列状态。

### 5.1 备份

`scripts/backup.sh` 使用运行中 PostgreSQL 的 `pg_dump`，并通过 RustFS 的 S3 API 下载附件桶的**当前对象**；不读取运行中的 RustFS 原始数据文件。它核对所选 Compose 的绝对路径与运行中 RustFS、PostgreSQL、API 容器的 `com.docker.compose.project.config_files` 标签，并核对 PostgreSQL 和 RustFS 的实际挂载卷。路径、卷或桶不匹配，以及任何传输失败，都会中止；未完成目录保留 `INCOMPLETE` 标记，不能用来恢复。若部署使用多份 `-f` 叠加文件，本脚本会因标签不等于单一所选文件而中止。使用前安装 `bash`、`jq`、`gzip`、`sha256sum` 和 Docker Compose v2；Docker 会按需获取 `amazon/aws-cli:2` 镜像。不传输出目录时默认写到部署目录的同级 `assay-backups`。

**在维护窗口暂停工单、草稿、附件上传与删除等写入**，待在途请求结束后运行备份，完成后再开放写入。PostgreSQL 和 S3 之间没有联合快照；在线写入可能产生数据库引用了尚未下载对象、或对象与数据库时点不一致的备份。S3 同步只保存当前对象字节，不保存历史版本、桶策略、对象 ACL/标签和完整的 Content-Type 元数据；本应用恢复所需的附件 MIME 同时保存在数据库中。方案依据：[RustFS 的 S3 客户端与 path-style 配置](https://docs.rustfs.com/en/developer/examples/boto3)、[AWS CLI `s3 sync` 行为](https://docs.aws.amazon.com/cli/latest/reference/s3/sync.html)。

```bash
set -euo pipefail
cd /data/assay
# 每次部署/升级都要从已审核的同版源码刷新脚本，不要沿用目录中的旧文件，
# 也不要从浮动的 main 分支下载。先在可信源码机上将 scripts/backup.sh
# 安全传送到 /data/assay/scripts/backup.sh.candidate，再在部署机校验：
test -d scripts && test ! -L scripts && test ! -L scripts/backup.sh
test -f scripts/backup.sh.candidate && test ! -L scripts/backup.sh.candidate
printf '%s  %s\n' \
  '5513e59f797ee08fbd723491ca75e96f9daf505af14f55fe1f09176b6927d7c9' \
  'scripts/backup.sh.candidate' | sha256sum -c -
# SHA-256 不匹配就停止；上面的哈希只对应本版文档审核的脚本。
install -m 700 scripts/backup.sh.candidate scripts/backup.sh
printf '%s  %s\n' \
  '5513e59f797ee08fbd723491ca75e96f9daf505af14f55fe1f09176b6927d7c9' \
  'scripts/backup.sh' | sha256sum -c -

# 场景 1，以及按 §2.3 部署的场景 2（安装时已把 Traefik 模板改名为 docker-compose.yaml）
bash scripts/backup.sh /data/assay-backups docker-compose.yaml

# 仅当你保留仓库模板原名并用 -f docker-compose.traefik.yaml 启动时，
# 才把第二参数改为 docker-compose.traefik.yaml。
```

输出目录每次使用唯一名称，包含 `db.sql.gz`、`objects/`、`compose.yaml`、`deployment.env`、`auth-secret.txt`、`backup-info.txt` 和 `SHA256SUMS`。`compose.yaml` 是所选 Compose YAML 的归档副本，已列入 SHA-256 清单；它供审计和对照使用，**不要直接用于隔离演练**。`backup-info.txt` 还记录了运行中 PostgreSQL 的用户名、数据库名和卷名，可用于恢复前校验。如果源 Compose 在备份期间变化，脚本保留 `INCOMPLETE` 并中止。`deployment.env` 是部署目录 `.env` 的副本；`auth-secret.txt` 取自**运行中的 API 容器**。两步验证密钥等数据依赖原 `AUTH_SECRET`，请连同备份一起加密异地保存、限制权限，不要提交到 Git。定时任务应检查退出码、确认没有 `INCOMPLETE`，并定期做恢复演练。若使用 `COMPOSE_PROJECT_NAME` 覆盖项目名，运行脚本时须保留同一环境变量。

### 5.2 隔离恢复演练

`psql` 导入 SQL 会修改目标数据库，S3 上传会修改目标桶。先把备份复制到测试位置，用下面的**固定、仅绑定本机端口的演练 Compose** 建立新项目。归档的 `compose.yaml` 仅供对照镜像版本、变量和卷来源；它可能包含生产 Traefik 网络与路由，不能传给演练命令，也不能复制到演练目录。如果固定模板与归档文件的镜像版本不符，先在模板副本中核对并调整镜像版本。

```bash
BACKUP=/data/assay-backups/backup-YYYYMMDD-HHMMSS-XXXXXX
DRILL=/data/assay-restore-drill
DRILL_PROJECT="assay-drill-$(date +%Y%m%d%H%M%S)"
set -euo pipefail
test -d "$BACKUP" && test ! -e "$BACKUP/INCOMPLETE"
(cd "$BACKUP" && sha256sum -c SHA256SUMS)
test ! -e "$DRILL" && test ! -L "$DRILL"  # 必须使用全新目录
mkdir -m 700 "$DRILL"
cp "$BACKUP/deployment.env" "$DRILL/.env"
chmod 600 "$DRILL/.env"

# 只编辑演练 .env：PUBLIC_URL=http://127.0.0.1:18088，
# AUTH_SECRET 使用 auth-secret.txt 中的原值，S3_BUCKET 与 backup-info.txt 一致。
# 禁用邮件发送（MAIL_PROVIDER=none），避免演练向真实用户发信。
${EDITOR:-vi} "$DRILL/.env"
```

将下面这份固定模板保存为 `$DRILL/compose.drill.yaml`。只在演练目录编辑它；不要从备份或当前仓库复制生产 Compose。模板只建立项目自己的网络和卷，Web 仅监听 `127.0.0.1:18088`。

```yaml
services:
  postgres:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: ${POSTGRES_USER:-assay}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:?set POSTGRES_PASSWORD}
      POSTGRES_DB: ${POSTGRES_DB:-assay}
    volumes: [pg-drill:/var/lib/postgresql/data]
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${POSTGRES_USER:-assay}"]
      interval: 10s
      timeout: 5s
      retries: 10
    networks: [drill]
  redis:
    image: redis:7-alpine
    volumes: [redis-drill:/data]
    networks: [drill]
  rustfs:
    image: rustfs/rustfs:1.0.0@sha256:8cc9801755448b71a786705ce76692c77e14936cccd87cf2fc31842e58f4d1ff
    command: ["/data"]
    environment:
      RUSTFS_ACCESS_KEY: ${S3_ACCESS_KEY:?set S3_ACCESS_KEY}
      RUSTFS_SECRET_KEY: ${S3_SECRET_KEY:?set S3_SECRET_KEY}
      RUSTFS_ADDRESS: ":9000"
      RUSTFS_CONSOLE_ENABLE: "false"
    volumes: [rustfs-drill:/data]
    networks: [drill]
  api:
    image: ${REGISTRY:-registry.cn-shenzhen.aliyuncs.com/willspace}/assay-api:${IMAGE_TAG:-latest}
    env_file: .env
    environment:
      NODE_ENV: production
      MAIL_PROVIDER: none
      PUBLIC_URL: ${PUBLIC_URL:?set PUBLIC_URL}
      DATABASE_URL: postgresql://${POSTGRES_USER:-assay}:${POSTGRES_PASSWORD}@postgres:5432/${POSTGRES_DB:-assay}?schema=public
      REDIS_HOST: redis
      REDIS_PORT: "6379"
      REDIS_URL: redis://redis:6379
      STORAGE_DRIVER: s3
      S3_ENDPOINT: http://rustfs:9000
      AUTH_BASE_URL: ${PUBLIC_URL:?set PUBLIC_URL}
      AUTH_TRUST_ORIGINS: ${PUBLIC_URL}
      APP_URL: ${PUBLIC_URL}
    depends_on:
      postgres: {condition: service_healthy}
      redis: {condition: service_started}
      rustfs: {condition: service_started}
    networks: [drill]
  web:
    image: ${REGISTRY:-registry.cn-shenzhen.aliyuncs.com/willspace}/assay-web:${IMAGE_TAG:-latest}
    ports: ["127.0.0.1:18088:80"]
    depends_on: [api]
    networks: [drill]
networks:
  drill: {}
volumes:
  pg-drill: {}
  redis-drill: {}
  rustfs-drill: {}
```

保存模板后继续；以下检查全部是只读的，任何一项失败都不要执行后面的 `up`：

```bash
cd "$DRILL"
test -f compose.drill.yaml
drill() { docker compose -p "$DRILL_PROJECT" -f "$DRILL/compose.drill.yaml" "$@"; }
CONFIG="$(drill config --format json)"
PROJECT="$(jq -r '.name' <<< "$CONFIG")"
SOURCE_PROJECT="$(sed -n 's/^project=//p' "$BACKUP/backup-info.txt")"
test "$PROJECT" = "$DRILL_PROJECT" && test -n "$SOURCE_PROJECT" && test "$PROJECT" != "$SOURCE_PROJECT"
# 硬性边界：只允许私有 drill 网络；无外部网络、Traefik 标签、host 网络或非本机端口。
jq -e '
  ((.networks // {}) | keys == ["drill"])
  and ((.networks // {}) | to_entries | all(.[]; (.value.external // false) != true))
  and ((.services // {}) | to_entries | all(.[]; (.value.network_mode // "") == "" and
    ((.value.labels // {}) | keys | all(.[]; startswith("traefik.") | not))))
  and ([.services[].ports[]?] | all(.[]; .host_ip == "127.0.0.1"))
  and (.services.web.ports | length == 1 and .[0].host_ip == "127.0.0.1" and .[0].published == "18088")
  and (.services.api.environment.MAIL_PROVIDER == "none")
  and (.services.api.environment.PUBLIC_URL == "http://127.0.0.1:18088")
  and (.services.api.environment.AUTH_BASE_URL == "http://127.0.0.1:18088")
  and (.services.api.environment.AUTH_TRUST_ORIGINS == "http://127.0.0.1:18088")
  and (.services.api.environment.APP_URL == "http://127.0.0.1:18088")
' <<< "$CONFIG" >/dev/null
jq -r '.volumes | to_entries[] | .value.name' <<< "$CONFIG"
test -z "$(docker ps -a --filter "label=com.docker.compose.project=$PROJECT" -q)"
test -z "$(docker volume ls --filter "label=com.docker.compose.project=$PROJECT" -q)"
# 如有同名容器、网络或卷则停止：
DRILL_NETWORK="$(jq -r '.networks.drill.name' <<< "$CONFIG")"
test -n "$DRILL_NETWORK" && ! docker network inspect "$DRILL_NETWORK" >/dev/null 2>&1
for VOL in $(jq -r '.volumes | to_entries[] | .value.name' <<< "$CONFIG"); do
  if docker volume inspect "$VOL" >/dev/null 2>&1; then echo "卷已存在：$VOL"; exit 1; fi
done
BUCKET="$(sed -n 's/^s3_bucket=//p' "$BACKUP/backup-info.txt")"
test -n "$BUCKET"
test "$(sed -n 's/^S3_BUCKET=//p' .env)" = "$BUCKET"
test "$(sed -n 's/^AUTH_SECRET=//p' .env)" = "$(cat "$BACKUP/auth-secret.txt")"
PG_USER="$(sed -n 's/^postgres_user=//p' "$BACKUP/backup-info.txt")"
PG_DB="$(sed -n 's/^postgres_db=//p' "$BACKUP/backup-info.txt")"
test -n "$PG_USER" && test -n "$PG_DB"
test "$(jq -r '.services.postgres.environment.POSTGRES_USER' <<< "$CONFIG")" = "$PG_USER"
test "$(jq -r '.services.postgres.environment.POSTGRES_DB' <<< "$CONFIG")" = "$PG_DB"

# 只启动新的数据库与 RustFS；不要先启动 API（API 会迁移并初始化空库）。
drill up -d --wait postgres rustfs
gzip -dc "$BACKUP/db.sql.gz" | drill exec -T postgres \
  sh -c 'exec psql -v ON_ERROR_STOP=1 -U "$POSTGRES_USER" "$POSTGRES_DB"'

# 从演练 Compose 配置取 RustFS 凭据，不在命令行参数或日志中打印密钥。
jq -r '.services.rustfs.environment |
  "AWS_ACCESS_KEY_ID=\(.RUSTFS_ACCESS_KEY)\nAWS_SECRET_ACCESS_KEY=\(.RUSTFS_SECRET_KEY)\nAWS_DEFAULT_REGION=us-east-1"' <<< "$CONFIG" > "$DRILL/aws.env"
chmod 600 "$DRILL/aws.env"
printf '[default]\ns3 =\n    addressing_style = path\n' > "$DRILL/aws.config"
RUSTFS_ID="$(drill ps --status running -q rustfs)"
test -n "$RUSTFS_ID"
docker run --rm --network "container:$RUSTFS_ID" \
  --mount "type=bind,src=$DRILL/aws.config,dst=/aws.config,readonly" \
  --env-file "$DRILL/aws.env" -e AWS_CONFIG_FILE=/aws.config \
  amazon/aws-cli:2 --endpoint-url http://127.0.0.1:9000 \
  s3api create-bucket --bucket "$BUCKET"
docker run --rm --network "container:$RUSTFS_ID" \
  --mount "type=bind,src=$BACKUP/objects,dst=/restore,readonly" \
  --mount "type=bind,src=$DRILL/aws.config,dst=/aws.config,readonly" \
  --env-file "$DRILL/aws.env" -e AWS_CONFIG_FILE=/aws.config \
  amazon/aws-cli:2 --endpoint-url http://127.0.0.1:9000 \
  s3 sync /restore/ "s3://$BUCKET/" --only-show-errors --no-progress

# 只读检查：SQL 内有附件表，S3 对象可列出；即使附件数为零也要确认两条命令成功。
drill exec -T postgres sh -c \
  'psql -v ON_ERROR_STOP=1 -U "$POSTGRES_USER" "$POSTGRES_DB" -Atc "SELECT count(*) FROM \"TicketAttachment\""'
docker run --rm --network "container:$RUSTFS_ID" \
  --mount "type=bind,src=$DRILL/aws.config,dst=/aws.config,readonly" \
  --env-file "$DRILL/aws.env" -e AWS_CONFIG_FILE=/aws.config \
  amazon/aws-cli:2 --endpoint-url http://127.0.0.1:9000 \
  s3 ls "s3://$BUCKET/" --recursive --summarize

# 再启动演练 API / Web，用测试账号检查登录和一份真实附件下载。
drill up -d api web
drill ps
rm -- "$DRILL/aws.env" "$DRILL/aws.config"
```

演练时若原备份使用不同 `S3_BUCKET`，也要在演练 `.env` 中设为 `backup-info.txt` 的 `s3_bucket`。验证完成后按运维流程处理隔离项目和含密钥的演练目录；删除前再次核对项目名、容器与卷的实际目标。生产恢复需要单独的停写窗口、目标清单、回滚计划和独立审批，不能直接套用此演练命令。

## 6. 常见问题

### 6.1 密码正确却登不进去

九成是 `PUBLIC_URL` 与实际访问地址不一致。检查：

```bash
grep PUBLIC_URL .env
docker compose exec api env | grep -E "AUTH_BASE_URL|AUTH_TRUST_ORIGINS"
```

三者必须和浏览器地址栏完全相同。改完 `docker compose up -d` 重建生效。

### 6.2 改了 .env 里的 ADMIN_PASSWORD 但登录还是旧密码

**这是预期行为。** `ADMIN_PASSWORD` 只在库里还没有该账号时用于创建，
之后改它不会影响已存在的账号。要改密码请登录后在个人中心改，
或用管理员身份在用户管理页重置。

### 6.3 换了 compose 文件后数据「全没了」

大概率是**卷名不一致**。两份 compose 的卷名不同：

| compose | 卷名 |
| --- | --- |
| `docker-compose.yaml`（场景 1） | `pg-data-prod` `redis-data-prod` `rustfs-data-prod` |
| `docker-compose.traefik.yaml`（场景 2 仓库模板；按 §2.3 安装后文件名为 `docker-compose.yaml`） | `pg-data` `redis-data` `rustfs-data` |

表中是 Compose 逻辑名；默认项目名为 `assay` 时实际卷名分别是 `assay_pg-data-prod` / `assay_rustfs-data-prod` 与 `assay_pg-data` / `assay_rustfs-data`。项目名由 `-p`、`COMPOSE_PROJECT_NAME`、文件内 `name:` 或目录名决定。拿一份覆盖另一份，Compose 可能挂载一组**空卷**，表现就是数据消失（原卷仍在）。
换 compose 前务必先比对：

```bash
docker compose config --format json | jq -r '.name, (.volumes | to_entries[] | .value.name)'
docker compose ps -q rustfs
docker volume ls --format '{{.Name}}'
```

### 6.4 附件上传失败

- 超过 **512 MB** 会返回 413
- 只允许 `.png .jpeg .jpg .txt .rar .zip .doc .docx .xls .xlsx .7z .mp4`
- 单张工单最多 5 个附件（正文内联图片不计入）

如果前面还有一层自己的 Nginx 反代，记得同步放开它的 `client_max_body_size`
（assay 自带的 web 容器里已经是 512m）。

### 6.5 看日志

```bash
docker compose logs -f api      # 后端，含迁移与 SLA 超时记录
docker compose logs -f web      # Nginx 访问日志
docker compose logs -f          # 全部
```
