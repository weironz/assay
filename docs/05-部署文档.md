# 部署文档

两种部署方式，按需选一种：

| 场景 | 访问方式 | 适用 | compose 文件 |
| --- | --- | --- | --- |
| **场景 1** | `http://服务器IP:8088` | 内网、测试、没有域名 | `docker-compose.yaml` |
| **场景 2** | `https://你的域名` | 生产，自动 HTTPS | `docker-compose.traefik.yaml` |

两者数据卷名不同（`*-prod` vs 无后缀），**不要互相覆盖**，详见 §6.3。

---

## 0. 前置条件

| 项目 | 要求 |
| --- | --- |
| 操作系统 | 任意支持 Docker 的 Linux |
| Docker | 20.10+，含 compose v2（`docker compose version` 能输出版本） |
| 内存 | 最低 2 GB，推荐 4 GB |
| 磁盘 | 20 GB 起。附件上传期间会占临时盘：**并发数 × 单文件大小**（单文件上限 512 MB） |
| 端口 | 场景 1 需要 8088（可改）；场景 2 需要 80 和 443 |

安装 Docker（如未安装）：

```bash
curl -fsSL https://get.docker.com | sh
systemctl enable --now docker
docker compose version   # 确认输出 v2.x
```

## 1. 场景 1：单机部署，直接 IP 访问

### 1.1 准备目录与配置

```bash
mkdir -p /data/assay && cd /data/assay

# 拉取 compose 与环境变量模板
curl -fsSLO https://raw.githubusercontent.com/weironz/assay/main/docker-compose.yaml
curl -fsSL  https://raw.githubusercontent.com/weironz/assay/main/.env.prod.example -o .env
```

也可以直接 `git clone https://github.com/weironz/assay.git` 后进入目录，
再 `cp .env.prod.example .env`。

### 1.2 填写 .env

用编辑器打开 `.env`，**至少改这 5 项**：

```bash
# 换成服务器的真实 IP 和端口，必须和浏览器地址栏完全一致
PUBLIC_URL=http://192.168.1.10:8088
WEB_PORT=8088

POSTGRES_PASSWORD=<强密码>
S3_ACCESS_KEY=<随机串>
S3_SECRET_KEY=<随机串>
AUTH_SECRET=<长随机串>
ADMIN_PASSWORD=<管理员初始密码>
```

生成随机串：

```bash
openssl rand -base64 32
```

> ⚠️ **`PUBLIC_URL` 是最容易踩的一项。**
> 它同时用作登录会话的签发地址和 CORS 白名单，必须与用户地址栏里的地址
> **逐字一致**（协议、IP/域名、端口都算）。写成 `localhost` 而实际用 IP 访问，
> 症状是「密码明明正确却登不进去」，且控制台报 CORS 错误。

### 1.3 启动

```bash
docker compose pull
docker compose up -d
```

首次启动时 API 容器会自动执行数据库迁移并写入初始数据（权限、角色、管理员、
默认队列、工单类型、分类、机房集群），需要 30 秒左右。

### 1.4 验证

```bash
# 容器是否都起来了
docker compose ps

# 迁移与初始化是否完成
docker compose logs api | grep -E "migration|Seed|已启动"
```

期望看到：

```
All migrations have been successfully applied.
✅ Seed 完成：权限/角色/admin/默认队列/类型/分类/机房集群
API 已启动: http://localhost:3000
```

再验证对外访问：

```bash
curl -I http://192.168.1.10:8088/          # 期望 200
curl -s http://192.168.1.10:8088/api/me    # 期望 {"message":"未登录",...,"statusCode":401}
```

`/api/me` 返回 401 是**正常的**——说明后端通了、只是没带登录态。

### 1.5 登录

浏览器打开 `http://192.168.1.10:8088`，用 `.env` 里的
`ADMIN_EMAIL` / `ADMIN_PASSWORD` 登录，**登录后立刻改密码**。

## 2. 场景 2：Traefik + 域名 + 自动 HTTPS

比场景 1 多两步：先有 Traefik，再把 assay 挂上去。

### 2.1 域名解析

先把域名 A 记录指向服务器公网 IP，并确认解析已生效：

```bash
dig +short tickets.example.com     # 应返回服务器 IP
```

> 解析没生效就启动会导致 Let's Encrypt 签发失败。**Let's Encrypt 对失败次数
> 有限流**，反复重试会被暂时锁住，届时只能干等，所以务必先确认解析再启动。

### 2.2 启动 Traefik（已有 Traefik 可跳过）

```bash
docker network create traefik-network

mkdir -p /data/traefik && cd /data/traefik
curl -fsSLO https://raw.githubusercontent.com/weironz/assay/main/deploy/traefik/docker-compose.yaml
echo "ACME_EMAIL=you@example.com" > .env

docker compose up -d
docker compose logs -f traefik      # 看有没有报错，Ctrl+C 退出
```

**已经有 Traefik 的话**，不用动它，只要确认这三样存在且名字一致，
因为 assay 的标签是按这些名字写的：

| 名称 | 类型 | 用途 |
| --- | --- | --- |
| `traefik-network` | 外部 docker 网络 | Traefik 与 assay-web 通信 |
| `websecure` | entrypoint | HTTPS 入口（:443） |
| `letsencrypt` | certresolver | 证书签发 |

名字不同就改 `docker-compose.traefik.yaml` 里 `web` 服务的 labels。

### 2.3 部署 assay

```bash
mkdir -p /data/assay && cd /data/assay

curl -fsSLO https://raw.githubusercontent.com/weironz/assay/main/docker-compose.traefik.yaml
mv docker-compose.traefik.yaml docker-compose.yaml
curl -fsSL https://raw.githubusercontent.com/weironz/assay/main/.env.prod.example -o .env
```

编辑 `.env`，与场景 1 的区别是**这两项**：

```bash
PUBLIC_URL=https://tickets.example.com     # 注意是 https
PUBLIC_DOMAIN=tickets.example.com          # 不带协议，Traefik 路由用
```

`WEB_PORT` 在这个场景下无效（web 不再对宿主机暴露端口，流量走 Traefik）。
其余密码、密钥项与场景 1 一样必须改。

启动：

```bash
docker compose pull
docker compose up -d
```

### 2.4 验证

```bash
docker compose ps
docker compose logs api | grep -E "migration|Seed|已启动"

curl -I https://tickets.example.com/            # 期望 200
curl -s https://tickets.example.com/api/me      # 期望 401 未登录
```

证书签发需要几十秒。如果暂时是自签证书或 404，先看 Traefik 日志：

```bash
docker logs $(docker ps -qf name=traefik) --tail 50
```

## 3. 邮件（可选）

不配置邮件系统照常可用，只是**邮箱验证和找回密码不可用**。

内网自建、没有发信服务时，建议在 `.env` 里显式关掉邮箱验证，
否则新注册用户收不到验证信、无法登录：

```bash
REQUIRE_EMAIL_VERIFICATION=false
```

需要发信时二选一（详见 `.env.prod.example` 内注释）：阿里云邮件推送
DirectMail，或任意 SMTP 服务。改完执行 `docker compose up -d` 生效。

## 4. 升级

```bash
cd /data/assay
docker compose pull
docker compose up -d
```

数据库迁移在 API 容器启动时自动执行，无需手工操作。

指定版本（推荐生产使用固定版本而非 `latest`）：

```bash
sed -i 's/^IMAGE_TAG=.*/IMAGE_TAG=1.3.2/' .env
docker compose pull && docker compose up -d
```

回滚同理，把 `IMAGE_TAG` 改回旧版本再 `pull && up -d`。

> **注意**：回滚镜像**不会回滚数据库迁移**。跨版本回滚前先确认旧版镜像
> 能兼容当前库结构，必要时从备份恢复。

## 5. 备份与恢复

数据在三个卷里：数据库、Redis（队列，可重建）、附件对象存储。
**必须备份的是数据库和附件**。

### 5.1 备份

```bash
cd /data/assay

# 数据库
docker compose exec -T postgres pg_dump -U assay assay | gzip > db-$(date +%F).sql.gz

# 附件：先确认卷名（两个场景不一样），再打包
VOL=$(docker volume ls --format '{{.Name}}' | grep rustfs)
echo "附件卷：$VOL"
docker run --rm -v "$VOL":/data -v "$PWD":/backup alpine \
  tar czf /backup/files-$(date +%F).tar.gz -C /data .
```

`.env` 也要一起备份——里面的 `AUTH_SECRET` 丢了会导致所有会话失效。

### 5.2 恢复

```bash
gunzip -c db-2026-09-02.sql.gz | docker compose exec -T postgres psql -U assay assay
```

## 6. 常见问题

### 6.1 密码正确却登不进去

九成是 `PUBLIC_URL` 与实际访问地址不一致。检查：

```bash
grep PUBLIC_URL .env
docker compose exec api env | grep -E "AUTH_BASE_URL|AUTH_TRUST_ORIGINS"
```

三者必须和浏览器地址栏完全相同。改完 `docker compose up -d` 重建生效。

### 6.2 改了 .env 里的 ADMIN_PASSWORD 但登录还是旧密码

**这是预期行为。** `ADMIN_PASSWORD` 只在库里还没有该账号时用于创建，
之后改它不会影响已存在的账号。要改密码请登录后在个人中心改，
或用管理员身份在用户管理页重置。

### 6.3 换了 compose 文件后数据「全没了」

大概率是**卷名不一致**。两份 compose 的卷名不同：

| compose | 卷名 |
| --- | --- |
| `docker-compose.yaml`（场景 1） | `pg-data-prod` `redis-data-prod` `rustfs-data-prod` |
| `docker-compose.traefik.yaml`（场景 2） | `pg-data` `redis-data` `rustfs-data` |

拿一份覆盖另一份，compose 会挂载一组**空卷**，表现就是数据消失（但原卷还在）。
换 compose 前务必先比对：

```bash
docker compose config | grep -A2 "source:"
docker volume ls | grep assay
```

### 6.4 附件上传失败

- 超过 **512 MB** 会返回 413
- 只允许 `.png .jpeg .jpg .txt .rar .zip .doc .docx .xls .xlsx .7z .mp4`
- 单张工单最多 5 个附件（正文内联图片不计入）

如果前面还有一层自己的 Nginx 反代，记得同步放开它的 `client_max_body_size`
（assay 自带的 web 容器里已经是 512m）。

### 6.5 看日志

```bash
docker compose logs -f api      # 后端，含迁移与 SLA 超时记录
docker compose logs -f web      # Nginx 访问日志
docker compose logs -f          # 全部
```

## 7. 安全清单

上线前逐项确认：

- [ ] `POSTGRES_PASSWORD` 已改为强密码
- [ ] `S3_ACCESS_KEY` / `S3_SECRET_KEY` 已改为随机串
- [ ] `AUTH_SECRET` 已改为长随机串（`openssl rand -base64 32`）
- [ ] `ADMIN_PASSWORD` 已改，且**首次登录后又改了一次**
- [ ] `.env` 权限收紧：`chmod 600 .env`
- [ ] 场景 1 若暴露在公网，前面加 HTTPS（或直接改用场景 2）
- [ ] 数据库与附件备份已配置为定时任务
