# 长时间挂起后无法恢复处理

`hold_ms` 原为 PostgreSQL INTEGER，按毫秒累计只能存约 24.9 天。单次长挂起，
或多次挂起的累计时间超过该值时，恢复处理会因 INT4 溢出失败，工单仍保持挂起。
旧详情页未显示状态切换错误，因此用户看不到失败原因。

修复将原列原地扩宽为 BIGINT，保留已有累计时长、工单、消息和附件。
恢复时仍把本次挂起时长精确加到未完成的 SLA 截止时刻，沿用处理人权限及并发检查。
列表和详情将 Prisma BigInt 转成 JSON 数字，保持原 API 字段格式。
页面显示操作进行中以及网络、服务错误、权限不足和状态冲突，并在失败时重新核对服务器状态。

## 升级与回退

- 按 [Taskfile 发布与 Ansible 部署流程](../../scripts/local-ci/README.md) 发布新版本并完成备份、恢复演练。
  新 API 必须包含本次迁移及重新生成的 Prisma Client；只改数据库不能修复旧 Client 的 INT4 编码限制。
- 迁移会短暂获取 tickets 表锁，应使用现有部署停写窗口。不会删除或重建工单记录。
- 保留 BIGINT 列，不盲目回退成 INTEGER。恢复超过 24.9 天的工单后，旧 Prisma Client
  可能无法读取扩大后的值，不应把旧 API 镜像视为可直接回退；须在隔离副本验证兼容性。
  不通过截断、清零累计时长或更改生产挂起日期绕过错误。
