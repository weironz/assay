# Samba 管理集成设计与实施计划

## 目标与边界

Assay 增加可选的 Samba 管理模块，Rust Agent 位于 `agents/samba`，独立构建和部署。管理员通过 Web 管理 AD 员工、组成员、共享、目录及 Windows ACL；员工可在绑定 AD 身份后自助改密。Assay 登录、工单与业务角色保持独立。

Agent 的业务逻辑由 Rust 实现。账号走 LDAPS，目录安全描述符走 SMB2/3，共享配置由 Rust 管理。运行时不调用现有 Python、Shell 管理脚本，不直接编辑 AD 数据库或 `security.NTACL`。

## 测试部署

文件服务器以独立 Compose 项目部署测试 AD、Agent、测试 Assay API/Web、PostgreSQL、Redis。测试 AD 使用独立域、数据卷与文件目录，不与公司 AD 共用任何数据。已有 Samba、Nextcloud 和生产 Assay 不参与发布。

浏览器通过文件服务器 IP 的 HTTPS 端口访问，证书包含 LAN / NetBird IP SAN，提供测试 CA 下载。AD 内部仍有自己的目录域名，这是 AD 的协议需求；用户访问网页不需要 DNS。API 与 Agent 仅在专用 Docker 网络通信，Agent 无公网管理端口；账号连接使用经 CA 校验的 LDAPS。

## 职责

| 组件 | 职责 |
|---|---|
| Assay Web | 用户/组/共享/目录/权限界面，确认变更，结果和审计，自助改密 |
| Assay API | 登录与专用 RBAC、受委派岗位的敏感操作二次验证、用户身份绑定、持久化操作记录、调用固定 Agent 地址；超级管理员凭有效会话直接管理 |
| Rust Agent | 类型化 API、机器凭据校验、请求去重、串行变更、AD/SMB 协议、受限本地文件和配置操作 |
| Samba | 身份、密码策略、组成员与 Windows ACL 的最终执行者 |

## 资源范围与数据保护

- AD 写操作仅允许配置的员工 OU / 用户组 OU；内置、高权限及 OU 外账号不可修改。
- 新员工先禁用创建，密码设置成功后启用；错误时保留可恢复的禁用账号。
- 默认不删除 AD 账号；支持停用/启用。组删除和目录删除限定受管资源；目录只允许删除空目录。
- 共享只修改 Agent 自己管理的 include 文件，不接管或覆盖其他共享；删除共享保留目录与文件。
- 本地文件操作限定根目录，拒绝路径穿越和符号链接；不提供任意命令、任意文件读写或 Docker socket。
- Windows ACL 通过 SMB 安全描述符接口，保留 owner/group、不可丢失未知 ACE；变更前后读取核对。
- 密码、机器密钥及 LDAP 凭据不进入日志、操作审计、请求持久化或 Git。
- 外部 AD 和本地状态无法组成一个数据库事务，操作状态必须区分完成、失败和执行结果不确定；不确定写入不得自动重放。

## 实施顺序与验收

1. 核对服务器资源，落地本设计，保留部署前只读基线。
2. 实现 Rust Agent：LDAPS CRUD、组成员、受管共享、目录、SMB ACL、鉴权、去重与保护边界。
3. 实现 Assay 独立权限与敏感操作二次验证、操作审计、管理页面及身份绑定/自助改密。
4. 增加 Compose、IP HTTPS 和隔离测试 AD 配置；发布测试镜像并部署 fileserver。
5. 真实浏览器测试创建/编辑/改密/停用员工、组成员、共享增删改、目录及 ACL、自助改密、无权限访问与错误处理。
6. 使用实际 SMB 登录验证授予/撤销权限；重启验证状态保留；复查公司原 AD/共享基线未变。
7. 每轮必要验证后提交并普通推送 `origin/main`；输出访问地址、测试结果、部署与恢复文档。

生产接入为后续独立部署动作。测试完成不代表自动将公司现有 AD 纳入写入管理。
