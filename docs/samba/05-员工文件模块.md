# 员工文件模块

“文件管理”是顶部业务模块，管理 AD 员工、用户组、共享目录、文件 ACL、登录账号关联及审计。平台管理负责 Assay 组织、系统账号、业务角色和可选身份集成。“共享文件”是同一模块下的可选员工入口，不需要 Samba 管理权限。

## 文件浏览与批量操作

- 首页直接展示当前账号获准访问的共享目录。进入后可切换网格或列表，用面包屑导航、搜索当前目录及排序。文件图标离线可用；电脑通过 SMB 保存文件后，点击刷新查看变化。
- 支持通过文件选择器或拖放上传多个文件。上传队列逐个执行，最多保留 100 项记录，可取消单项、取消全部及清除已结束记录；每项显示进度、目标路径与最终结果。发送进度达到 100% 后仍需等待服务器确认。
- 上传期间可浏览其他目录；每个任务保留加入队列时的目标共享和路径。单项失败不丢弃后续任务，登录失效则停止剩余上传。离开文件管理或关闭页面会取消未完成任务；当前版本不支持断点续传、整文件夹拖入或后台跨页面上传。
- 网格和列表都提供复选框，可选择本页项目，批量移动或删除。切换目录、搜索条件或分页会清除选择，刷新时也会去掉失效项目。批量移动填写同一共享内已存在的目标文件夹路径；留空表示共享根目录。
- 批量操作需确认，随后逐项执行并分别展示成功、失败或未执行结果。权限由员工 SMB 会话实时校验，每次写入保留原有服务端审计；部分成功不回滚，失败不自动重试。同名文件不会覆盖，非空目录不会递归删除。离开页面会停止尚未开始的批量命令，已发出的命令仍可能完成。
- 上传取消、超时或连接中断可能发生在服务器提交前后，请刷新核对真实状态后再操作。任务与文件只保存在页面内存，不写浏览器持久存储。

### Filestash 参考范围

参考 [Filestash](https://github.com/mickael-kerjean/filestash) 的存储操作接口、上传队列和多选交互思想，自行实现前端 `FileStorage` 适配层，将状态查询、连接、目录读取、命令、上传及下载地址生成从页面中分离。该层复用现有 Assay API，不表示已支持多种服务端存储驱动。

没有复制或嵌入其 AGPL-3.0 源码，也没有引入 Filestash 服务、额外镜像或容器。认证、员工 SMB 会话和管理权限边界保持现有设计，不采用把 AD 密码保存在可解密 Cookie 或连接参数中用于重连的方案。本轮未实现在线文档编辑、预览、缩略图、外链或文件版本。

## 身份和调用

1. 可选 AD 统一登录会在登录时自动建立文件会话，见 [可选 AD 统一登录](06-可选AD统一登录.md)。以下步骤适用于本地或 OIDC 登录。员工先登录 Assay。管理员预先将其 Assay 用户关联到指定 AD objectGUID；相同用户名或邮箱不会自动关联。
2. 首次进入“共享文件”输入本人 AD 密码。API 只接受密码，AD DN、GUID、账号名和可管理共享范围由后端确定。Rust Agent 内的文件模块用该员工 DN 进行 LDAPS 绑定，核对实际 GUID、账号名、启用状态，再用本人凭据建立加密 SMB 会话。
3. 文件操作只通过员工 SMB 会话完成，Samba 判断共享准入和 Windows ACL。没有管理 Agent 或本地文件系统的读写回退。管理与员工文件模块合并到同一 Rust 进程，进程持有管理凭据及受管目录访问权限；两类接口保持独立密钥和请求校验，员工文件操作没有管理员凭据或本地文件系统回退。合并减少了进程级隔离，不再声明员工模块在操作系统层接触不到管理资源。容器不挂载 Docker socket。
4. AD 密码只参与当次验证，不写数据库、Redis、磁盘或日志。网关只保留 LDAP 连接和非 DFS SMB 连接及协商密钥；Redis 保存与单个 Assay Web 会话绑定的随机网关凭证。浏览器拿不到该凭证。服务端密码字符串在请求处理后丢弃，Rust 自有输入使用 zeroize；协议库可能有临时内存副本。
5. 文件连接跟随当前 Assay Web 登录期限保留，默认上限 7 天，不再因闲置 15 分钟或使用满 1 小时单独失效。有效文件请求按当前登录的剩余期限续期；使用工单等其他业务模块触发登录滑动续期时，也会维护已有文件连接，不创建新的连接；网关后台只维护已认证的 LDAP/SMB 连接，不延长登录期限，不保留密码用于重连。每次操作仍核对本人 AD 状态、pwdLastSet 和有效 tokenGroups；API 同时核对身份关联和共享访问策略。账号、密码、组成员、共享策略或身份关联变化会撤销连接；LDAP/SMB 真正失联、网关重启或登录失效后需要重新建立连接。续期采用当前凭证的比较更新，退出、断开或并发建立新连接后，旧请求不能恢复旧凭证或撤销新凭证。传输仍受当前登录期限、断开和 Samba 检查约束。
6. 公司账号统一登录成功后直接展示文件夹，不提供文件连接面板、“其他连接方式”、独立 AD 密码框或“断开文件会话”入口。文件身份确实失效时，自动撤销当前登录并回到统一登录页；登录后返回文件列表。文件服务暂时不可用时保留业务登录，显示服务状态和重试；公司登录成功但可选文件服务失败时也不会循环登录。退出 Assay 会撤销文件凭证，后台维护不能恢复已撤销的连接；重新公司登录时仅用本次输入的密码建立本人的新文件连接。本地或 OIDC 登录仍可使用本人 AD 密码的独立文件入口，并可单独断开。API 多副本通过 Redis 共享会话引用。

## 范围

提供共享文件夹首页、网格/列表视图、目录浏览、搜索分页、单文件流式上传和下载、新建文件夹、同共享内移动或重命名、删除文件或空文件夹。只列出当前启用且本人可读的 Assay 管理共享。隐藏临时上传文件，不支持 DFS、符号链接或重解析目录、跨共享移动、递归删除和覆盖现有目标。

进入“共享文件”先展示当前文件会话已获准访问的共享目录卡片，不自动选中首个共享，也不提前读取各共享内的文件。点击文件夹进入；面包屑和“返回上一级”可回到所有共享目录。支持网格/列表切换并在当前浏览器记住布局；搜索仅筛选当前目录名称，列表可按名称、修改时间、大小排序，文件夹优先，每页 48 项。点击文件可下载，“更多操作”提供下载、移动/重命名和删除；工具栏提供新建文件夹、上传和刷新。图标为本地 SVG，支持手机与深色模式，没有缩略图或内容预览服务。

Web 操作完成后刷新当前列表。电脑通过 SMB 保存的同一份文件，在点击“刷新”或重新进入目录后读取最新状态；当前不轮询、不监听文件变更，也不是本地磁盘同步客户端。

当前单实例最多 100 个员工文件会话，每次验证最多 64 个启用的受管共享，单目录最多 10000 项。新增加的共享在重新验证后发现；修改已连接共享的访问策略会要求重新验证。该限制不影响 Assay 工单或管理员目录操作。

上传默认单文件 200 MiB，可配置到 512 MiB；后端不将整个文件装入内存。上传先写同目录随机临时文件，完整接收和 flush 后以不覆盖方式 rename 发布；失败和取消会尝试删除临时文件。进程被强制终止或服务器断电时仍可能留下隐藏临时文件，需要管理员在确认无传输任务后清理，不能据此认为有完整业务文件。

文件写操作执行前持久化审计，下载也记录审计。连接中断时写操作可能已经提交，审计保留 uncertain，不自动重试；应先刷新目录核对。此版本是基础员工文件入口，尚不提供企业网盘的版本历史、回收站、同步客户端、外链或在线编辑。

## 部署

默认 `FILES_ENABLED=false`，不开启不会改变现有工单或身份模型，也没有数据库迁移。需要同时启用 `SAMBA_ENABLED=true`。部署前备份现有数据库和附件；不得通过重新运行测试域 bootstrap 升级已有环境。

统一 Rust Agent 与 Samba 靠近部署，Assay API 主动调用其文件模块，员工浏览器不直连 Agent。防火墙方向：

| 发起方 | 目标 | 用途 |
| --- | --- | --- |
| 员工浏览器 | Assay Web HTTPS 443 | 登录与文件操作 |
| Assay API | 统一 Agent HTTPS 配置端口及 `/files` 路由 | 专用服务密钥认证、员工会话与流式传输 |
| Agent 文件模块 | Samba TCP 445 | 本人身份的加密 SMB |
| Agent 文件模块 | AD TCP 636 | 本人 LDAPS 验证与状态检查 |

隔离 Compose 内使用 `http://agent:8080/files`，不发布宿主机端口；跨主机部署必须使用受信任 TLS 反向代理。API 仍使用 `FILES_GATEWAY_URL`、`FILES_GATEWAY_TOKEN_FILE` 配置，这些兼容名称现在指向进程内文件模块，不再代表额外容器。文件服务密钥至少 32 字符，与管理 Agent 密钥不同；Agent 启动时拒绝复用同一个密钥。TLS 代理须保留 Authorization 和 X-File-* 头，关闭请求/响应体日志。生产使用单个有状态 Agent 实例；多个实例必须设计会话路由及管理写入一致性，不能直接轮询。

在现有 `agent.json` 中增加 `files` 对象即可开启员工文件模块。以下 JSON 是该对象的内容（不是替换整份管理配置）：

```json
{
  "token_file": "/secrets/files-token",
  "smb_server": "192.168.10.225",
  "domain": "COMPANY",
  "ldap_url": "ldaps://ad.company.example:636",
  "ldap_ca_file": "/tls/ca.crt",
  "users_dn": "OU=Employees,DC=company,DC=example",
  "max_file_bytes": 209715200,
  "web_session_max_seconds": 604800
}
```

`web_session_max_seconds` 默认 604800，须为 1–604800 秒，作为当前登录剩余期限以外的网关上限。新 API 创建 `follow_web_session` 连接；仅受服务认证、绑定到同一 owner/凭证且通过当前 AD 状态检查的请求可续期。旧网关调用方的非 Web 连接仍使用兼容参数 `idle_seconds`（默认 900）和 `lifetime_seconds`（默认 3600）；它们不会被新请求静默升级成长连接。API 与文件网关应配套升级，先升级网关再升级 API；已丢失的旧连接需要重新公司登录一次。保留连接期间仍占用网关会话名额，退出不用的登录可及时释放。

统一镜像使用 `agents/samba/Dockerfile` 构建，命令为 `docker build -t assay-samba-agent:<version> agents/samba`。新 Compose 只运行一个 Agent 进程，内部提供管理与文件路由；删除旧 helper/file-gateway 服务。容器根文件系统只读，仅挂载的受管目录可写，drop ALL capabilities 后保留 KILL 与 DAC_OVERRIDE；配置中的 AD 主机名必须匹配证书，禁止跳过 CA 检查。

隔离新部署的 `setup.py` 将文件配置写入 `agent.json.files`。API 的 `FILES_ENABLED=false` 仍为默认值；启用员工入口后执行 `docker compose up -d`，无需文件服务 profile。已有环境使用 `migrate-unified.py --apply` 升级并保留旧配置与操作记录备份，不重新初始化域。Web 代理继续支持 512 MiB 请求上限、流式传输及 600 秒超时。

真实联调脚本为 `deploy/samba-test/tests/files-e2e.cjs`，依赖之前 UI 测试生成的私有 fixture。通过 `SAMBA_E2E_PRIVATE_DIR` 和 `SAMBA_E2E_ADMIN_PASSWORD_FILE` 指定本地私有路径，不把测试凭据提交仓库。

文件管理器界面专项回归为 `deploy/samba-test/tests/file-browser-e2e.cjs`，复用已有 QA 员工与共享，只在新建 QA 子目录中验证根目录授权展示、导航、网格/列表、真实上传下载/重命名/删除、刷新、键盘菜单及 390px 布局，结束后移除本次生成的文件。支持 fixture 已显式切换为 AD 登录的环境，不调整用户组、ACL 或共享配置。

文件会话专项回归包括 `file-session-e2e.cjs`（真实公司登录、Web 期限、刷新复用、自动回到统一登录、旧 Cookie 撤销、退出、服务故障重试和防登录循环；配置可信私有 `SAMBA_E2E_SESSION_PROBE` 后，可只调整生成 QA 账号的会话缓存以加速验证业务模块滑动续期）与 `gateway-lease-e2e.cjs`（独立临时网关使用 2 秒闲置/3 秒旧绝对期限，验证新连接跨旧时限、续期约束、owner 隔离、绝对失效、真实维护周期和断开防恢复）。后者在隔离 API 容器内执行，通过 stdin 传入生成的 QA 员工身份及密码，不写凭据到磁盘，不发布临时网关端口；不在主业务网关修改测试时限。Rust 时钟注入测试另外验证跨两小时和完整 Web 期限边界。
