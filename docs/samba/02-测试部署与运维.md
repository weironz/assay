# Samba 管理测试部署与运维

## 拓扑

fileserver 上的独立 Compose 项目 `assay-samba-test`，目录 `/data/assay-samba-test`，包含测试 AD、统一 Rust Agent（单容器、单进程）、独立 Assay API/Web、PostgreSQL 和 Redis。测试域为 `ASSAY.TEST`；AD 的内部域名不需要公网 DNS，用户访问网页只使用 IP。

- 公司内网：`https://192.168.10.225:8446/`
- NetBird：`https://100.70.220.77:8446/`
- 测试 CA：`http://192.168.10.225:8096/test-ca.crt`，安装到受信任根证书后访问 HTTPS。
- Assay 管理员：`admin@assay.test`，初始化密码保存在服务器 `/data/assay-samba-test/secrets/test-admin-password`，仅 root 可读。

网页 8446 是唯一业务入口；8096 用于 CA 下载和 HTTPS 跳转。Agent、数据库、Redis 均不发布宿主机端口。测试 AD 在内部网 `172.30.225.0/24` 中，SMB/LDAP 与公司原容器、数据目录完全分离。统一 Agent 使用内部网络，不再部署 helper/file-gateway 容器；管理与文件接口使用独立服务密钥。

## 可复现部署

隔离 AD 默认固定当前已验证的 Samba 4.24.7（linux/amd64）：`quay.io/samba.org/samba-ad-server@sha256:d43a6af4b4253c79a1a143c1021936b025e88cf3f68da1b9aab1720f3d810f24`。不再使用可变的 `default-fedora-amd64` 标签。上游容器项目的 `v0.9` 包含 Samba 4.24.3，不是 Samba 4.24.7 的后续版本。

新测试环境可通过 `SAMBA_TEST_IMAGE` 显式选择另一个已验证的镜像摘要；初始化程序将实际选择写入新部署 `.env`，使一次性建域与后续 Compose 使用同一引用。其他架构应提供对应摘要。已有测试域不要重新运行 setup.py；公司生产 AD 由其独立 Compose 管理，Assay 生产部署不会替换或升级 AD 镜像。

先构建三个镜像（或将已构建镜像通过 `docker save/load` 传入服务器）：

```sh
docker build -t assay-samba-agent:test agents/samba
docker build -t assay-api:samba-test apps/api
docker build -t assay-web:samba-test apps/web
```

将 `deploy/samba-test` 复制到服务器，执行：

```sh
sudo python3 deploy/samba-test/setup.py --lan-ip 192.168.10.225 --vpn-ip 100.70.220.77
sudo docker compose --project-directory /data/assay-samba-test up -d
```

初始化程序只允许固定的测试目录，已初始化时拒绝覆盖凭据。官方 Samba CLI 仅用于一次性创建隔离测试域与 OU，不是 Agent 运行时依赖。密码和证书私钥现场生成；不要将 api.env、database.env、secrets、tls 私钥、AD 数据或数据库卷提交 Git。测试域将密码最短修改间隔设为 0，便于重复测试；公司原密码策略不变。

## Web 操作

顶部“文件管理” → 管理概览，进入员工、用户组、目录、账号关联与审计。全局“平台管理”保留 Assay 组织与系统账号配置：

1. 员工账号：开户、员工详情、工号/邮箱/部门/岗位/联系方式编辑、停用/启用、管理员重置 AD 密码。
2. 用户组：创建/说明修改、组详情、成员列表与搜索分页、批量添加和移出、逐行移出、删除未被目录引用的空组。
3. 共享目录：目录详情、访问组列表、创建/修改共享、空目录增删、查看和修改 Windows 权限、移除/恢复共享。
4. 登录账号关联（原身份绑定）：管理员将 Assay 用户明确绑定到 AD objectGUID，不按同名或邮箱自动关联。
5. 员工个人设置 → 安全 → 公司 AD 密码：核对旧 AD 密码后改密，Assay 登录密码保持独立。忘记或过期无法认证的 AD 密码由管理员在 Web 重置。
6. 操作记录：查看 queued/running/succeeded/failed/uncertain 和执行结果。

超级管理员（`admin`）的管理写入和绑定凭有效 Web 会话及受信页面来源直接执行，无需二次验证；`samba_manager` 等受委派岗位仍需一次性二次验证。普通 requester 可访问自己的绑定和改密；启用可选模块后，还可验证本人 AD 密码使用“共享文件”，不能读取管理目录或执行管理员动作。`samba_manager` 岗位仅提供 Samba 管理权限，不授予 Assay 用户/角色管理权或 AD Domain Admin 身份。

员工文件服务的配置、开墙方向与启用步骤见 [员工文件模块](05-员工文件模块.md)，默认关闭。

## 验证与恢复

```sh
sudo docker compose --project-directory /data/assay-samba-test ps
sudo docker compose --project-directory /data/assay-samba-test logs --tail=50 api agent
sudo docker compose --project-directory /data/assay-samba-test restart agent api
```

重启 Agent/API 不删除 SQLite、AD、PostgreSQL 或文件数据。重建 AD 容器时同时重建 Agent，使其加入新的 PID namespace；先等待 AD healthy，再启动 Agent。`down` 后可用 `up -d` 恢复；不要使用 `down -v` 或删除部署目录。

Web 通过 Docker DNS 动态解析 API 地址，API 重建导致 IP 变化后最多等待 5 秒刷新，无需手动重启 Web。Web 健康检查通过 Nginx 请求 API readiness，同时检查数据库、Redis 和附件存储；仅静态页面可访问时不会误报 healthy。

备份需同时保存 Compose、私有环境配置/密钥、AD etc/state（含 NTACL/xattrs）、managed、shares、agent-state，以及 PostgreSQL 和 Redis 数据卷。恢复保留域 SID、用户 SID 与 Unix ID，不重新 provision 旧域。测试部署不替代公司生产备份。

## 自动化测试

`deploy/samba-test/tests/web-e2e.cjs` 使用真实浏览器操作所有管理页面，`smb_probe.py` 使用独立 SMB 客户端验证有效权限；`security-e2e.cjs` 验证写入边界与批量成员校验；`layout-e2e.cjs` 用浏览器只读模拟大列表，检查分页、详情、手机导航和断外网时 Logo 加载。测试密码和截图写入指定私有目录，不进 Git。

安装测试依赖：在 tests 目录安装 package.json 中的 Playwright，再运行 `npx playwright install chromium`，Python 安装 `smbprotocol`。设置 `SAMBA_E2E_ORIGIN`、`SAMBA_E2E_PRIVATE_DIR` 和 `SAMBA_E2E_ADMIN_PASSWORD_FILE` 后运行脚本。探测客户端默认连接 `127.0.0.1:11445`；可通过 SSH 转发到测试 AD 的 `172.30.225.10:445`，不接触公司 SMB 端口。

测试浏览器仅对自签测试证书设置 ignoreHTTPSErrors；证书链和 IP SAN 另用 CA 校验检查。公司内网浏览器应正常信任测试 CA。云环境浏览器保留公共代理，仅为经授权 NetBird 到达的测试 IP 设置 bypass。

## 分离服务升级为统一 Agent

不要重新运行 setup.py。先加载同版本的统一 Agent/API 镜像，将仓库中的 `migrate-unified.py` 与新版 `compose.yaml` 放在服务器私有升级目录，执行 `sudo python3 migrate-unified.py` 检查计划，再带 `--apply` 执行。默认镜像为 `assay-samba-agent:unified-test`、`assay-api:unified-test`，可用 `--image` / `--api-image` 指定。升级备份保存在 `/data/assay-samba-test/backups/unified-agent-*`；仅重建 Agent/API，不重建 AD 或数据卷。员工的旧 SMB 连接需通过正常公司登录重新建立。


用户组使用专用 `groups_dn` OU 时，部署示例将 `group_prefix` 设为空，以 OU 和 AD 受保护对象检查划定管理范围。Web 新建组按填写的名称原样提交，不自动添加前缀；名称格式及重复名称会在表单明确提示。旧部署若仍显式配置前缀，页面会展示该限制；解除时仅清空 Agent 的 `group_prefix` 并使配置生效，现有组名、SID、成员和共享授权不做迁移。共用 `CN=Users` 容器的兼容部署仍须保留非空前缀，不能直接取消范围保护。Agent 重启会使内存中的网页文件会话失效，需要重新登录公司账号建立连接；Windows 直连 SMB 和 Samba AD 本身无需重启。

AD 的 `sAMAccountName` 在域内由员工账号、用户组和计算机账号共同使用。已有员工账号 `test` 时，不能再创建同名用户组；这属于名称占用，不是平台管理员权限不足。Web/API 会交叉检查受管员工与用户组，Agent 在创建前按域查询名称，并将 LDAP 68 明确分类为 `AD_OBJECT_EXISTS`，覆盖其他 OU 的占用和并发重名。系统不会自动改名或修改已有账号。
