## 统一账号登录入口（2026-10-16，北京时间）

- 登录页合并为一个账号/密码表单，支持用户名或邮箱，不再要求选择公司、本地账号。后端按已保存的账号及目录关联确定认证归属；已关联员工使用固定 AD GUID 验证，目录失败不转试本地密码。同名、邮箱或目录别名冲突不自动合并。主动关闭 AD 配置后保留原来的独立本地使用方式。

- 公开注册默认关闭，API 的 `AUTH_ALLOW_REGISTRATION=true` 同时控制注册链接和公开注册接口；内部管理员自举及受保护的管理员创建账号继续可用。忘记密码页明确公司密码由管理员处理；AD 启用时不发送关联员工的本地重置邮件。OIDC 保留可选按钮，不增加账号来源选择。
- API 114 项通过、4 项可选集成跳过，Web 56 项及两端构建通过。另在全新临时 PostgreSQL/Redis 上应用完整迁移并通过 9 项认证集成测试，验证真实密码、Cookie、会话 epoch、本地/AD MFA、注册开关、禁用回退及目录故障下的管理员登录；AD 验证在该独立测试中使用内存替身，不连接公司域。临时容器结束后移除。

## Rust 管理与文件服务合并（2026-10-16，北京时间）

- 管理 API、共享配置本地操作和员工文件传输合并为一个 Rust 二进制、一个镜像、一个容器及一个进程。管理接口保持 `/v1/...`，员工文件接口位于 `/files/v1/...`；删除独立文件网关构建目标、镜像 Dockerfile 和 Compose helper/file-gateway 服务。文件模块可通过 `agent.json.files` 配置开启，不配置则不注册文件路由。
- 本地操作在进程内串行执行，阻塞操作使用 blocking task，调用方断线不提前释放串行锁。管理与文件服务密钥必须不同，不能跨路由使用；员工文件仍使用本人 LDAPS/SMB 会话，无管理员身份或本地文件内容回退。统一进程持有受管本地目录及管理凭据，不再具有原来的进程级权限隔离。容器根文件系统只读，drop ALL 后仅保留 KILL、DAC_OVERRIDE，无宿主机端口或 Docker socket。
- Rust 19 项测试、Clippy 与格式检查通过；API 104 项通过、3 项可选集成跳过，两种镜像构建成功。新增 6 项真实合并回归验证管理快照与 ACL、进程内共享配置写入及 smbd 重载、管理创建目录与员工视图一致、128 KiB 流式上传下载、员工越权拒绝及原 AD/组/共享/根 ACL 保留。10 项文件会话回归、11 项文件管理器回归再次通过。
- 隔离环境实际确认一个 Rust 进程，旧 helper/file-gateway 容器已移除；跨服务密钥访问均返回 401。SIGTERM 优雅停止约 0.12 秒，重启后仍只有一个 Rust 进程，测试 AD 与公司原 AD 均未重启或替换。
- 升级脚本保留旧配置、SQLite 操作记录备份、部署元数据及镜像引用，健康检查失败可恢复旧部署。仅更新隔离 Agent/API；Web、AD 与数据卷不重建，没有数据库迁移或生产发布。原有工单及关联记录、资产库存、账号凭据和手工角色的行数及内容摘要一致。QA 文件全部清理，共享配置已恢复。
- 旧内存 SMB 会话在切换时失效，通过正常公司登录重新建立；不保存 AD 密码用于重连。下方旧阶段关于独立 helper/文件网关容器的描述由本节替代。

## 已修正的实际问题

1. 连续操作中旧二次验证回调关闭新弹窗：等待整个操作与刷新完成后再关闭，并拒绝旧目录请求覆盖新路径状态。
2. 父目录 ACL 修改不能直接撤销已有文件的继承授权：增加 Rust 的子项继承传播，保留显式/拒绝条目和受保护分支。
3. Samba 会将缺少 AUTO_INHERITED / AUTO_INHERIT_REQ 的继承 ACE 视作显式项：按 Windows 语义同时发送两个标志，并通过真实文件写入验证。
4. 长操作采用异步任务与轮询，接受请求不等于执行成功；重启或超时不确定任务不自动重放。

详细原始测试输出、运行凭据和基线位于执行工作区私有目录，不提交 Git。可复现测试入口为 `deploy/samba-test/tests`。
