# Samba 管理测试验收记录

测试日期：2026-10-14 UTC。部署位于 fileserver `/data/assay-samba-test`，独立域 `ASSAY.TEST`，Samba 4.24.7，Rust Agent 0.1.0。Web 使用 LAN / NetBird IP HTTPS，无公网域名要求。

## 验收结果

- 18 项真实浏览器功能场景通过：管理员登录、员工创建/编辑/停用/启用/改密、组增删改及成员调整、共享增改/移除/恢复、嵌套目录创建及空目录删除、Windows DACL 授予/撤销、共享只读、身份绑定、员工自助改密、审计脱敏。
- 13 项安全边界场景通过：匿名及普通用户越权拦截、写入二次验证、验证用途与一次性限制、操作 ID 去重/冲突、任意命令与路径穿越拒绝、非空组删除保护、陈旧 ACL 版本拒绝、受管范围外对象保护、操作记录归属、自助改密不能选择其他身份。
- 独立 SMB 客户端验证员工真实读写权限：读取授权、写入授权、降为只读、移除授权、恢复授权、组成员撤销/恢复、共享只读和文件保留均符合预期。
- Rust：7 个测试通过，格式检查和 Clippy `-D warnings` 通过；API：72 个测试通过、3 个既有集成测试跳过；Web：32 个测试通过。
- Agent/API 重启前后用户、绑定、操作记录、AD 员工/组及共享配置逐项一致；重启后 SMB 文件仍可读取。
- 公司原 AD 身份属性（含 SID、GUID、UID/GID、状态）、组成员、Samba 配置和共享根目录 NTACL 哈希与部署前基线一致。原 Samba 容器及现有业务目录没有纳入测试写入。

## 已修正的实际问题

1. 连续操作中旧二次验证回调关闭新弹窗：等待整个操作与刷新完成后再关闭，并拒绝旧目录请求覆盖新路径状态。
2. 父目录 ACL 修改不能直接撤销已有文件的继承授权：增加 Rust 的子项继承传播，保留显式/拒绝条目和受保护分支。
3. Samba 会将缺少 AUTO_INHERITED / AUTO_INHERIT_REQ 的继承 ACE 视作显式项：按 Windows 语义同时发送两个标志，并通过真实文件写入验证。
4. 长操作采用异步任务与轮询，接受请求不等于执行成功；重启或超时不确定任务不自动重放。

详细原始测试输出、运行凭据和基线位于执行工作区私有目录，不提交 Git。可复现测试入口为 `deploy/samba-test/tests`。

## 使用范围

这是独立测试环境的验收，不是公司原 AD 的生产切换。账号停用保留历史身份；只管理配置范围内账号/组和 Agent 受管共享。既有生产共享的显式接管需另行设计与验证。单次权限传播最多 10000 子项，保留显式授权和受保护子目录；成员变化需重新建立 SMB 登录会话。
