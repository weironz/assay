# 员工登录账号、用户组和 SMB 共享重命名

本功能修改原对象，禁止删除重建。员工和组以 AD objectGUID 定位；共享使用持久 ID，名称和实际目录路径分别保存。新旧名称、文件服务器地址及连接影响均在 Web 预检查中展示。

## 管理员操作

1. 在“文件管理 → 员工账号 / 用户组 / 共享目录”进入对象详情。
2. 点击“重命名登录账号 / 重命名用户组 / 重命名共享”，输入新名称。
3. 执行“预检查”，核对旧名称、新名称、共享地址、物理路径和连接影响。
4. 安排员工在合适时间重新连接，勾选影响确认后提交。管理权限和当前部署的二次验证策略保持不变；没有重新要求全局管理员验证密码。
5. 等待操作记录显示“已完成”。请求超时或结果待核对时，先查看同一个操作编号，不要换编号重复写入。

名称使用 2–48 个字符，以小写字母开头，仅包含小写字母、数字、下划线或短横线。不自动添加前缀、不裁剪、不静默改变大小写。遗留部署如果仍配置组名前缀，改名也遵守该配置。员工与组共享整个 AD 域的 sAMAccountName 名称空间，预检查会检查相互冲突，以及员工 UPN 冲突。

系统账号、受 AD adminCount 保护的对象及管理范围以外的对象继续受保护。sysvol、netlogon、global、homes、打印服务和 scan 扫描入口不可通过共享改名操作更名。组的名称引用涉及 scan 时也拒绝此操作，避免改变打印机扫描入口。

### 员工登录名

修改原对象的 sAMAccountName 和用户 UPN。已有 UPN 保留其域后缀；原来没有 UPN 的账号使用当前 AD DNS 域。显示姓名、邮箱、工号、UID/GID、SID、GUID、启用状态、主组和密码属性都不写入。

**内部 CN/DN 保持不变**：CN 不是登录名，不必与 sAMAccountName 相同。本功能不移动或重建 AD 对象，保留 DN 可以让组成员和其他 DN 引用保持稳定。例如，登录名变为 test_user 后，内部 DN 仍可为 CN=test,OU=Employees,...，这是预期行为。显示姓名的调整继续使用独立的“编辑员工资料”。

改名后使用新登录名和原密码。Assay 的 User.id、身份绑定、工单等业务关联以及手工授予的角色保持原样；平台只更新绑定账号名称，并清理该 GUID 的目录资料缓存。已建立的个人 Web 文件连接可能需要重新登录，新登录会使用更新后的身份。

### AD 用户组

修改同一个组的 sAMAccountName，保留组 CN/DN、SID、GUID、gidNumber、组类型、说明及成员。Windows 文件 ACL 使用 SID，改名不重新初始化 ACL。

同时更新受管共享的访问组名称，以及既有共享配置中域限定的 valid users、invalid users、admin users、read list、write list、force group、force user 引用。按完整 principal token 替换，避免 alpha 错误匹配 alpha_extra，或连续改名发生连锁替换。未知的名称引用方式或动态 include/copy 配置会拒绝预检查，需先由部署管理员核对。

Assay 业务角色映射仍以原组 SID 为键，只更新展示名称。个人文件准入版本使用组 SID，组标签改变不应自行使仍有效的 Web 文件连接失效。

### SMB 共享名

只改变 UNC 中的共享名。例如 `\\fileserver\test` 变为 `\\fileserver\projects`，新入口继续指向原 test 物理目录。不移动、复制或重建文件，不修改所有权、只读/隐藏属性、访问组或 Windows ACL。

共享详情链接使用稳定 ID。访问升级前按名称保存的详情链接时，页面先转为稳定 ID，改名后仍停留在同一个详情页。受管共享登记记录独立保存 path，后续编辑说明、共享准入和恢复共享均继续使用该路径。

既有公司共享的原始配置及导入清单保持只读。启用更名后，在受管配置目录中生成经过校验的配置副本和名称登记，通过受控 include 引用该副本；原始共享配置保留作对照。仅允许对已导入的业务共享改名，原始物理路径和未涉及的配置行保持不变。原始配置或受管副本被外部修改时停止写入，防止覆盖运维人员的改动。

新 SMB 连接使用新名称，旧名称不再提供新的共享入口。已有连接及打开文件可能暂时保留旧句柄；本功能不主动关闭文件、不重启 AD。员工需更新快捷方式和映射盘。Web 个人文件连接重新建立后会列出新共享名；旧共享名不会保留为额外别名。

## 部署参数与升级

API、Web、统一 Rust Agent 都需要升级到支持重命名的版本。数据库无需更换用户 ID，也没有复制业务数据的迁移。

Agent 保持一个常驻 Rust 进程。镜像中的 testparm 是固定的一次性配置校验程序，在提交前短暂运行，不是另一个后台服务；运行时不调用部署 Python 脚本，不挂载 Docker socket，不启动 Samba 管理守护进程。

校验器镜像包含默认的空 state/cache/lock/PID 目录，防止将 Agent 容器缺少运行目录误报为 Samba 配置错误；它们不包含 AD 数据库。自定义 Samba 运行目录使用镜像构建参数 SAMBA_VALIDATION_DIRS 提供，不关闭 testparm 逻辑校验。

在现有 agent.json 中显式配置 rename。以下是示例，请按站点实际挂载设置，不能直接照搬地址：

```json
{
  "rename": {
    "main_config": "/existing/smb.conf",
    "samba_config_root": "/etc/samba",
    "samba_managed_dir": "/etc/samba/assay",
    "include_file_name": "include.conf",
    "testparm": "/usr/bin/testparm",
    "client_address": "fileserver.example.com",
    "storage_display_root": "/data/samba-ad/shares"
  }
}
```

- main_config 是 Agent 可读的主配置；samba_config_root 和 samba_managed_dir 是 Samba 容器看到的路径，不能混用。
- include_file_name 应指向既有受管 include 包装文件。文件名、主配置路径、客户端地址、存储展示根均由部署参数提供。
- 共享登记、共享配置、include 包装文件，以及内部的 rename-catalog.json / external-renamed.conf 必须使用不同文件名，预检查会拒绝冲突。
- client_address 只用于展示员工 UNC 地址，不改变 SMB 服务监听。省略时使用既有 smb_server；建议填写员工实际使用的地址。
- storage_display_root 只用于说明物理目录；不提供时展示 Samba 可见存储根。它不会改变实际挂载或触发移动。
- 不配置 rename 时继续运行旧功能，重命名按钮不启用。prepare.py 仅供全新部署生成这些配置，**不得在现有生产目录重新执行 --apply**。

升级步骤：

1. 确认没有 queued/running 管理操作和未处理的 rename-pending.json。保存数据库、Agent 操作库、agent.json、受管共享配置/登记、include 包装文件、外部共享导入清单以及当前镜像摘要的备份。
2. 文件改名本身不触碰数据内容，本次小范围升级不要求为每次发布重新复制数十 GB 文件；文件数据仍使用独立的日常备份策略。
3. 拉取 CI 成功的三个镜像，按 digest 固定。更新 Agent 配置，保留所有当前令牌、目录绑定参数、网络及持久卷。
4. 仅重建 Assay Agent/API/Web。Agent 重建会丢失内存中的个人 SMB 会话，员工需要重新登录；Samba/AD、数据库和文件卷不重建。
5. 用独立 qa_ 对象验证三类操作，核对原账号和其他共享的摘要。分别记录代码 SHA、各组件镜像和验收结果。

## 一致性、中断与回滚

所有管理写入继续通过 Agent 串行队列和幂等操作 ID。重命名还要求对象版本；过期页面、同名对象和重复使用不同参数的请求 ID 都会拒绝。AD 属性使用一次 LDAP Modify 的旧值删除/新值添加作为名称比较条件，并使用 GUID 绑定定位原对象，避免同 DN 删除重建后误改另一个对象。对第三方管理工具的并发操作采取版本检查和遇到差异停止的策略；不是跨 AD 和文件系统的全局分布式锁。

提交前会展开受控 include 并运行 testparm。配置验证失败不会修改 AD。提交前持久化 rename-pending.json，保存非敏感身份资料和配置变更的前后字节；不记录密码、密码哈希或私钥。文件写入使用临时文件、fsync 和原子替换，随后热加载主进程及现存 smbd worker，不强制踢出员工。

执行失败时按原 GUID 补偿 AD 名称并恢复本次配置字节。只有当文件仍等于本次的修改前/后版本时才恢复；出现第三方编辑时保留恢复日志并阻止后续写入，不能用旧备份覆盖新改动。Agent 再次启动会检查恢复日志：已提交事务补齐成功结果，未提交事务尝试补偿；无法证明安全时拒绝启动，需管理员核对。同一操作不自动重新执行。

API 使用持久操作记录对平台名称关联做事务同步。API 重启后后台只查询 Agent 结果并补齐原用户/原组 SID 的名称，不重新发起 AD 写入；数据库和缓存不可用时不会提前报告整个操作已完成。

回滚分两种情况：

- **上线后尚未进行任何更名或新格式登记写入**：恢复本次备份的 Agent 配置和三组件镜像摘要，只重建这三个服务。
- **已使用更名功能**：优先回滚 API/Web，保留支持新登记格式的 Agent、配置及持久状态。旧 Agent 不认识稳定共享 ID 和独立路径，不能直接降级。若要完全退回旧 Agent，先在新 Agent 上按稳定 ID 逆向改名，逐项验证共享路径及外部引用，再安排专门的登记格式迁移；不要直接恢复 AD 数据库、覆盖业务数据库或用删除重建代替回滚。

恢复日志含站点配置，只放在受限目录，不提交 Git。源配置、网络白名单、NetBird、扫描目录和未选择的账号不应因验证被修改。

## 验收

`deploy/samba-test/tests/rename-e2e.cjs` 要求显式指定目标 origin 和私有测试配置；只生成 qa_ 对象。其独立 Python SMB 客户端从 stdin 接收密码，不把凭据写到命令行或输出。

验收包括：GUID/SID/数字映射/成员/状态/密码时间戳对比、原密码登录新账号名及原 User.id/角色、组引用与角色映射同步、授权与拒绝、共享改名前后 inode/内容/ACL、已打开句柄、旧 UNC 的新连接拒绝、非法名/跨用户组重名/保护项/过期版本/权限不足/幂等请求。

`rename-failure-e2e.cjs` 仅允许对回环地址上的 ASSAY.TEST 隔离域运行：配合只读登记文件挂载验证 AD 改名后的补偿，配合普通员工 LDAP 绑定验证权限不足。故障由测试部署提供，生产 Agent 没有故障注入开关。Rust 单元测试覆盖提交前后中断恢复及第三方修改时保留写入隔离。

`rename-external-e2e.cjs` 使用预先导入的独立 qa_ 共享，覆盖只读/隐藏、valid users 和 admin users 引用、原配置只读、inode/内容/ACL，以及改名后恢复测试名称。完整验收结束后，由测试目录所有者核对路径和内容并清理只读验证文件。

Windows 人工验收前必须关闭相关文件，断开该服务器的旧 SMB 连接，核对保存的凭据，再明确使用目标员工账号连接。不能把旧会话成功当成新名字验证成功，也不能把复用其他账号导致的拒绝当成目录创建失败。
