# 部门目录禁删与领导访问

## Web 入口和权限模型

“文件管理 → 共享目录 → 目录名称 → 目录与权限 → 设置用户组权限”增加
**读写（禁止删除）**。本模式从共享根目录应用到全部现有子目录和文件，避免上级
“删除子项”权限绕过保护；包括已有独立 ACL 的分支。

勾选“同步收紧其他非管理授权”会同时收回 Everyone、其他组、文件所有者等允许条目中的
删除、删除子项、修改权限和更改所有者能力。未勾选且有冲突授权时拒绝操作。
现有子文件保持原有读写限制，不会因批量禁删而新增读取原本不可见文件的权限。

不对部门组设置 blanket deny：领导即使也是部门成员，仍可通过独立管理授权完全控制。
管理服务、SYSTEM、本域 Administrator/Domain Admins/Enterprise Admins 和 BUILTIN
Administrators 保留管理权限。额外管理主体由 Agent 私有配置 `acl_admin_sids` 指定：

```json
{"acl_admin_sids":["S-1-5-21-111-222-333-1200"]}
```

这是示例 SID，不能原样用于生产。领导应加入独立 AD 组，并将组 SID 配置为管理主体，
同时在共享 `valid users` 中准入该组。不得把整个 Domain Users 或普通部门组设为例外。
Web 请求不能传入任意例外 SID。组成员决定实际权限；改配置不自动撤销旧 ACL，调整范围
还须核对 ACL 和旧 SMB 登录令牌。文件管理权限不等于 Assay 平台或 AD 域管理员角色。

## 预检查、提交与恢复

Agent 使用真实 SMB 安全描述符接口修改 DACL，保持数据、owner/group/SACL 和已有 deny。
OWNER RIGHTS 规则限制普通文件所有者隐含的权限管理能力。高级 ACE、空 ACL、越界、
重解析点、并发变化或超过配置容量的树需先审核；不能忽略失败继续宣布成功。
Agent 的部署参数 `acl_max_entries` 默认 10,000（含根），审核容量后可提高至 100,000。
普通请求不能覆盖此限制；禁删操作及异步只读 `acl.preview` 最长一小时，期间持续保留
操作与恢复日志。大目录使用异步预检查，避免长 HTTP 请求超时被误判为失败。
目录树先完整预检查，提交后再次遍历并回读 Samba 的实际结果。

共享须实际加载 `acl_xattr`，例如 `vfs objects = acl_xattr recycle`。仅设置模块参数不够。
已有共享的 VFS 调整需先备份、验证配置，并在无打开文件时刷新连接。

原始和计划安全描述符保存在 `agent-state/acl-journals/<请求 UUID>.json`，连同每项路径、
最终状态；逐项进度单独保存在同目录的 `.progress.json`，避免每写一项都重写全树备份。
文件 0600、目录 0700。普通失败按已观察到的修订逆序恢复；并发修改、
进程中断或恢复不完整时标为 uncertain，并暂停后续 ACL 写入。
不得手工把未完成日志改为 committed 来解除保护。

人工恢复先停止该树的普通写入，核对请求和 SMB 路径，再经已认证 SMB 安全描述符接口
恢复原 DACL；保持当前文件数据和 owner/group/SACL，不用旧数据库或历史文件树覆盖在线写入。
回读验证后登记恢复结果。完整灾备另保留原配置、AD、数据库、附件及文件 xattr。
日志、备份和私有副本均不得加入 Git、Release 或公开 Actions artifact。

## 既有文件服务器的 Task / Ansible 流程

阿里云工单站点的 `local:deploy` 与公司栈 `local:deploy:samba` 是不同目标。
共同配置见 [发布说明](../../scripts/local-ci/README.md)。公司栈须已有
`deployment-input.json` 和 `compose.yaml`，不会重新 provision AD 或替换数据卷。

```bash
# 从环境注入 DEPLOY_HOST/USER/DIR/KNOWN_HOSTS/SSH_KEY，非 root 时设置 DEPLOY_BECOME=true。
# LOCAL_CI_UPGRADE_BACKUP_DIR 必须是仓库外的空 0700 目录；离线传镜像用 DEPLOY_OFFLINE=true。
task samba:backup          # 完整备份、隔离恢复验证、下载私有副本和旧 API/Web 镜像
# 如备份后仅改了工具源码，运行 samba:backup:verify：重新恢复验证同一份主机备份，
# 重新校验本地副本并比对两端 SHA256，不重复下载镜像；原运行镜像变化则拒绝。
task local:ci             # 最终提交的完整 CI
task test:upgrade         # 私有数据库/附件副本的迁移和旧程序兼容演练
task local:publish        # 发布明确版本镜像与 Release，不自动部署
task local:deploy:samba   # 只升级 API/Web/Agent，核对原记录和本地附件

# 示例范围，实际使用本次获授权的部门和领导账号。
export SAMBA_POLICY_DEPARTMENTS='["finance","sales"]'
export SAMBA_POLICY_LEADERS='["boss_one","boss_two"]'
export SAMBA_POLICY_LEADERSHIP_GROUP=company_leadership
# 仅在核对实际规模、容量与维护窗口后设置；默认 10000，最多 100000。
export SAMBA_POLICY_MAX_ENTRIES=100000
task samba:runtime         # 核对已部署发布镜像、健康和备份，再登记本次运维源码
task samba:policy
task samba:verify           # 临时身份逐共享验证 SMB 权限，随后删除测试身份和验证文件
```

备份通过 XFS reflink 保留文件、AD 和应用的权限/xattr/内容，并验证恢复副本。
Samba 仅在一致快照期间短暂停顿，随后恢复；实际停顿写入证据。升级会另外停写 API/Web
做最终数据库/附件备份。失败的应用恢复不覆盖数据库，原数据容器/卷保持。
新部署 `api_runtime_gid` 默认 1000，须匹配非 root API 镜像的实际组；API 读取的三个机密
采用 root 所有、该组只读 0640，管理密码仍为 root 0600，避免接口因 EACCES 失效。
Docker 29/containerd 可能用 OCI index/manifest 摘要作为运行 ID，经典 Docker 用 config 摘要。
演练会逐级校验归档的 index → Linux amd64 manifest → config 哈希链；部署同时记录
发布 config ID 与主机实际运行 ID，不能仅因格式不同放宽镜像检查。
经典镜像归档导入 containerd 后若生成新的 OCI 描述符，部署工具会导出主机实际镜像，
校验其完整描述符哈希链仍指向发布的精确 config 摘要，然后才允许启动；不能用标签相同代替身份校验。

大目录预检查依赖大量小型 SMB 请求。Agent 的 TCP 传输启用 `TCP_NODELAY`，避免
分开发送消息头和正文触发 Nagle/延迟 ACK，放大逐文件扫描延迟。该修正不降低 SMB
加密、签名或权限检查要求；仍保留目录容量、只读预检查、并发修订和恢复日志限制。

部署后的纯运维修复不需要覆盖已发布版本或重新构建相同程序。先提交工具改动并执行
`task test:deployment`，再运行 `samba:runtime`：核对原 Release、完整 CI 和升级演练的
来源一致，只允许发布提交以来变更运维工具/文档，应用源码变化则拒绝；主机重新核对
运行镜像 ID、健康、恢复验证备份及两端副本 SHA256。新运维记录与原发布提交分别登记，
不修改或伪造原构建/部署记录。后续 policy/verify 要求当前运维记录。
若控制端断线而远端异步部署仍在运行，先检查原操作目录及异步任务，不重放部署。
原任务成功写入 `result.json` 后，指定原目录执行：

```bash
export SAMBA_RESUME_OPERATION="$DEPLOY_DIR/rollback/task-deploy-YYYYMMDDTHHMMSSZ-abcdef"
task test:deployment
task samba:resume
```

`resume` 核对原部署参数、完整发布/演练记录、数据保留证明、当前真实镜像和备份 SHA256，
只生成当前运维源码的运行证明，不重新拉镜像、迁移或重建容器，也不补写假冒的旧源码记录。
未完成、失败、已回退或当前运行镜像变化都会拒绝。完成后可继续 policy/verify。
空源码差异同样可以核对，中文路径按 NUL 分隔读取，不依赖 Git 的路径引号显示。

回退到不认识 `acl_max_entries` 的旧 Agent 时，要先恢复兼容的私有 Agent 配置；
只回退镜像而保留新字段会导致旧程序拒绝启动。应用回退与 ACL 恢复是独立操作，
回退应用不自动撤销已提交的文件权限，也不能用旧文件树覆盖在线文件。

既有外部共享若有重命名覆盖层，批量维护同时更新原配置、稳定 ID 清单、重命名清单和
最终覆盖配置，并在隔离环境挂载两层配置执行 testparm。维护准入限制同样覆盖两层，
避免旧覆盖配置覆盖领导准入或绕过维护期间的限制；不改变共享 ID、别名或物理路径。

升级既有本地附件命名卷时，检查 Compose 的 Docker copy-up 行为。对已初始化、
所有权正确的现有卷可使用长格式挂载 `volume.nocopy: true`，避免新镜像目录元数据
复制改变卷根目录；保留原 UID/GID。新建空卷仍须按 API 的 UID/GID 初始化，不能
直接照搬现有卷的升级配置。在线拉镜像前检查 Docker daemon 镜像代理及实际拉取结果，
普通 curl 连接 Docker Hub 失败不能代替 daemon 拉取检查。

批量策略排除 common、scan、test 和系统共享。存在打开的 SMB 文件时，在目录策略写入前
拒绝执行。维护期间短暂停 Web，仅对目标部门限制普通 SMB 准入，保留管理服务访问，
防止预检查后出现新写入；公共与扫描配置保持原样。全量预检查通过才逐目录提交，
结束或失败均恢复准入和 Web。完成目录、失败点、原配置、文件内容/所有权校验和 ACL 备份 ID
保留在本次 rollback 操作目录。两位领导通过独立组取得所选目录准入及完全控制，不改用户密码/SID。

## 验收与限制

`task test:samba-acl` 使用独立 SMB 客户端，仅允许明确的隔离 `ASSAY.TEST`：
设置 `SAMBA_NO_DELETE_TEST_DIR`、`SAMBA_AGENT_TEST_ORIGIN`，按需设置
`SAMBA_TEST_PYTHON` 和测试 Compose override；禁止将 QA 初始化脚本用于公司域。
测试覆盖新旧文件读写/新建、员工删除/重命名/修改权限被拒，以及同时属于部门组的领导可删除。
生产另须核对实际成员、所有目标根 ACL、共享准入和文件数据；验证只操作新建的受控临时文件，
不索取或重置既有员工密码。Windows 旧连接可能持有旧组令牌，成员变更后须重新建立 SMB 登录。

禁删不是 WORM/不可变存储：保留写入仍可能覆盖或截断文件；重命名、移动和部分 Office
通过临时文件替换原文件的保存方式可能失败。保护历史内容还需快照、版本或异地备份。

### 已生成配置的旧模板修复

升级后若改名预检提示 `managed config changed outside Agent`，先运行当前运维源码的
`task test:deployment`、`task samba:runtime`。仅当缺少已知的回收站 mtime 默认项时，可设置
`SAMBA_RECONCILE_PREVIEW_GROUP` 为一个现有自定义组，再运行 `task samba:reconcile`。
入口核对已验证备份、保留原配置、调用当前 Agent 的完整渲染预检，再热加载；未知漂移不覆盖。
它只补齐 `recycle:touch_mtime = yes`，影响今后被回收文件的 mtime，不修改现有文件或 ACL，
不重启 AD。修复失败恢复原配置并重新开放 Web；程序镜像、发布来源和历史部署记录不改写。
