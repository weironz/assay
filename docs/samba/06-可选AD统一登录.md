# 可选 AD 统一登录与业务权限

Assay 默认使用本地账号，工单、资产和库存不依赖 AD、Samba 或文件网关。`DIRECTORY_AUTH_ENABLED=false` 为默认值；OIDC 仍可独立配置。当前 LDAPS 接入面向具有 objectGUID、sAMAccountName 和 tokenGroups 的 Active Directory / Samba AD，并非任意 OpenLDAP schema。

## 开关与部署

API 环境变量参见根目录 `.env.example` 的「公司 AD 登录」。启用时必须配置 LDAPS 地址、受信 CA、域名、搜索范围、专用只读查询账号及其密码文件；不允许明文 LDAP、跳过证书验证或 URL 内携带凭据。将密码文件和 CA 只读挂载到 API；API 需要到域控 TCP 636 的连通性，无需员工浏览器访问 LDAP。只读账号只需查询指定范围的用户、用户组及构造属性 tokenGroups，不应授予域管理权限。

身份认证、`SAMBA_ENABLED` 管理和 `FILES_ENABLED` 文件入口分别配置。认证由 API 通过标准 LDAPS 完成；已有 Rust Agent 继续管理目录/共享/ACL，独立文件网关继续以员工身份执行 SMB。没有文件需求时，不必部署文件网关。

测试 Compose 可叠加 `deploy/samba-test/compose.directory.yaml`；先在隔离 ASSAY.TEST 域准备专用只读账号，在私有 `api.env` 设置 `DIRECTORY_BIND_DN`，准备 `secrets/directory-password`。不要套用到公司的原有域或重新 provision 域控。

## 登录及账号关联

启用后登录页默认显示公司账号，同时保留本地账号入口。可使用短账号、域前缀账号或 UPN。LDAPS 查询确定 DN、objectGUID 和账号状态，随后用员工自己的密码绑定并再次核对 GUID，防止同名账号重建或并发替换。启用 TOTP 的账号在签发会话、建立 SMB 连接之前完成第二因子验证，也支持一次性备用码。

首次登录按稳定的域标识和 objectGUID 建立 `DirectoryIdentity`，再关联 Assay 内部 `User.id`。新建员工没有本地凭据或 AD 密码副本，默认获得提单人角色。目录邮箱仅作为资料，不视为已验证邮箱；未配置邮箱时使用稳定的内部占位地址。

已有业务账号应先由管理员在「平台管理 → 身份与访问 → 关联已有业务账号」明确选择业务账号和公司账号，首次公司登录即可复用原 User.id；此流程无需启用 Samba 管理或文件网关。历史上在「文件管理 → 账号关联」建立的明确 AD GUID 关联也可沿用。不会按同名或相同邮箱自动合并；发生邮箱冲突时拒绝登录，管理员应先完成明确关联。关联过程保留现有工单、库存记录、手工角色及本地凭据。启用 AD 期间，已关联员工统一通过公司身份登录，旧本地密码和旧本地会话不能绕过 AD 状态检查；安全验证与 MFA 设置也使用 AD 密码。首次关联会递增会话 epoch，使旧会话和待完成的本地 MFA 挑战失效。关闭 AD 集成后，历史本地账号可重新使用原本地凭据，纯 AD 新用户则由管理员明确设置本地密码。建议将本地应急管理员独立保留，不关联域身份。

AD 修改密码、账号停用、过期、锁定或要求改密会影响域会话；角色和状态查询最多缓存 30 秒。域身份服务不可用时拒绝继续授权域会话，本地应急登录仍可用。禁用 AD 登录会使已有域登录会话失效，不会删除身份记录或业务用户；独立本地登录和 API Token 只使用手工角色，AD 授予的角色不再生效。AD 改名保持业务 ID，删除后重建的同名 AD 用户不会继承原 GUID 的业务账号。

## 业务角色

在「平台管理 → 身份与访问」选择 AD 组和 Assay 业务角色。映射使用组 SID，员工有效组来自 tokenGroups，包含嵌套安全组和主组。组改名不丢映射，删除后重建的同名组不自动继承权限。

目录授予的角色单独保存，授权时与手工角色合并；退出组或移除映射只撤销目录授予部分。角色定义和数据范围仍遵循现有工单、资产、库存规则。平台超级管理员不开放通过 AD 组自动授予，仍需显式授权。映射变更需要角色管理权限和一次性安全验证，并记录审计。

域账号安全验证和 TOTP 沿用 Assay 的限流、会话 epoch、重放保护及敏感操作机制。AD 启用期间，已关联员工不能通过本地登录或管理员本地重置接口产生绕过公司身份的入口。停用 AD 集成后，管理员可在系统账号页面明确设置新的本地登录密码，继续沿用原 User.id，并补充本地业务角色；不会自动把 AD 密码转换为本地密码。AD 自助改密仍可通过已配置的 Samba 管理模块执行。

## 一次登录访问文件

启用管理和文件模块后，公司登录会建立该员工的 SMB 会话并直接进入 `/files`。浏览、上传、下载、移动和删除均使用本人的 SMB 身份，由 Samba 校验权限。密码只在当前认证请求及 SMB 建连过程中使用，不写数据库、Redis、日志或浏览器存储；Redis 只保存受当前 Web 会话约束的能力引用和非秘密身份状态。

文件服务故障不阻断工单等业务登录，用户可稍后重新验证文件访问。SMB 会话过期、连接失效或身份/授权发生变化后需要重新验证；不会在后台长期保存密码以自动重连。OIDC 身份令牌本身不能建立 SMB 会话，本地或 OIDC 登录仍需验证关联的 AD 密码。

## 菜单与数据升级

顶部顺序为工单、资产、备件库存、文件管理。原「公司目录与文件」和「我的文件」合并为「文件管理」，左侧分「文件访问 / 共享文件」与「管理配置」。员工只见文件访问，管理员另见概览、员工账号、用户组、共享目录、账号关联、操作记录。关闭文件入口仍可保留管理。原 `/samba/...` 与 `/files` 链接继续有效。

迁移仅新增 `directory_identities`、`directory_group_roles` 两张表，不改写现有用户、凭据、手工授权、工单或库存记录。升级先备份数据库；正常通过既有 migrate deploy 流程执行，禁止用重建数据库或删除数据卷的方式部署。关闭 AD 功能即可恢复本地使用方式，保留新表以便审计和再次接入。
