# 用户角色分配

入口：平台管理 → 系统账号与角色（`/users`）。仅具备 `user:manage` 权限的账号可以访问角色目录和分配角色。

## 新建用户与用户列表

主页面只展示用户列表、搜索和右上角“新建用户”按钮，不常驻创建表单。搜索支持姓名、邮箱、角色名称/标识，以及公司账号或继承角色。

点击“新建用户”后在右侧打开抽屉；手机端占满屏幕。步骤如下：

1. 基本信息：姓名（至少 2 个字符）、邮箱、初始密码（至少 6 位），校验通过后才能进入下一步。
2. 分配角色：搜索并选择岗位角色，点击“新建用户”提交。至少选择一个角色；与现有后端契约一致。

两步间切换保留输入及角色选择。底部按钮固定可达，搜索角色时按回车不触发创建。取消、关闭、Esc 或遮罩关闭不额外确认，未提交的草稿及密码不写入本地存储，再次打开是空表单。创建期间锁定控件及关闭操作；失败时保留输入并展示错误，不自动重试；成功后关闭抽屉、清除列表搜索、刷新用户并显示成功提示。不增加密码或验证器二次验证。

## 交互方式

- 新建用户与编辑角色共用列表式选择器，不再横向平铺所有复选框。
- 输入角色名称、标识、权限码或权限范围说明即可实时搜索；支持多个关键词，所有关键词都匹配才显示。
- “全部角色 / 已选角色”切换只影响显示，不修改选择结果。搜索隐藏的角色仍会提交。
- 每行展示角色名称、稳定标识及权限范围，可展开只读权限码明细。
- 右侧显示已选角色及数量，可逐项移除；窄屏自动调整为上下布局。
- 管理员角色被选中时显示完整管理权限提示，不增加额外确认弹窗。
- AD 组继承的角色独立展示，不混入手动角色列表，也不通过本页移除。
- 用户列表使用紧凑角色标签，完整标识可通过提示查看。

保存前修改仅存在于当前表单；取消、Esc 或点击遮罩会丢弃未保存的修改。保存中禁用编辑，避免重复提交；保存失败保留选择并展示错误。弹窗支持焦点循环、焦点返回、背景滚动锁定。列表支持加载、失败重试及无匹配提示。

## 权限边界

本次只调整角色分配与权限展示，不提供自定义角色、权限策略编辑、批量授予所有权限或自动提权。

`GET /api/roles` 保留固定系统角色顺序及原有 `id/name/description` 字段，新增 `permissions: string[]`。权限码从数据库角色关联读取，不由前端硬编码。接口仍要求 `user:manage`，返回值不包含用户资料或凭据。

手动角色保存仍使用 `PATCH /api/users/:id` 的 `roleNames`，后端现有 RBAC、会话认证及最后一名管理员等保护规则不变。角色权限合并不代表绕过工单归属、可见范围等业务检查。

## 回归检查

1. 新建抽屉第二步搜索 `requester`，选择后搜索另一个角色，再切回已选，原选择不丢失。
2. 编辑用户搜索无结果，右侧已选摘要仍显示完整选择；直接保存提交完整 `roleNames`，不只是当前搜索结果。
3. 展开权限码，再使用键盘 Tab、Shift+Tab、Esc，确认焦点留在弹窗内并在关闭后返回入口。
4. 添加或移除管理员角色时展示对应提示，但不额外要求密码或验证器；最后一名管理员保护仍由后端执行。
5. AD 继承角色不可通过手动选择器移除。
6. 检查四种语言、桌面与 375px 窄屏、浅色及深色主题，弹窗内部滚动且按钮可达。
7. 前端 `bun run build && bun test test`；后端 `pnpm build && pnpm test`。自动测试覆盖搜索、隐藏选项保留、500 个角色目录、翻译结构，以及角色目录权限码契约。

8. 新建用户第一步必填校验、两步间保留内容、角色搜索回车不提交、创建失败后手动重试、请求中连续提交只发一次请求、成功后刷新列表及取消后重新打开为空表单。

浏览器验收使用隔离页面与测试数据替代 API，验证实际 UsersPage、CreateUserDrawer 和 RoleSelector 组件，不创建真实账号或修改真实用户权限。新建用户前端测试另覆盖身份字段去空格但密码不变、基础校验及姓名/邮箱/手动角色/继承角色搜索。
