# 工单分享链接：实现、使用与运维

工单分享链接（Ticket Share Link）用于把一张工单的**公开讨论**交给未登录的外部人员只读查看，例如客户确认处理进展、供应商协助排障，或跨组织临时沟通。

它不是外部协作账号，也不是公开工单门户：访问者不能登录、回复、下载普通附件、查看内部备注或修改任何工单字段。

## 1. 使用方式

在工单详情页的状态操作区点击“分享”：

1. 填写可选的链接名称，例如“客户确认”或“供应商排障”；
2. 选择有效期：1、7、30、90 天或永不过期；
3. 创建后立即复制完整链接；
4. 将 `https://<域名>/share/<token>` 发送给指定外部人员；
5. 不再需要时，在同一面板点击“撤销”。撤销即时生效。

完整链接只在创建成功后显示一次。后续列表只显示名称、创建时间、有效期和状态，**不会再次显示 URL**；如丢失链接，请新建一个并撤销旧链接。

## 2. 谁可以分享

分享是“将工单内容带出登录边界”的能力，因此不跟随普通查看权限自动授予。

| 身份 | 创建/查看/撤销分享链接 |
| --- | --- |
| 提单人 | 可以，仅限本人创建的工单 |
| 当前处理人 | 可以，仅限当前负责的工单 |
| 主管 `supervisor` | 可以，任意工单 |
| 管理员 `admin` | 可以，任意工单 |
| 协作成员 `COLLABORATOR` | 不可以 |
| 关注人 `FOLLOWER` | 不可以 |
| 工单观察员 `ticket_viewer_all` | 不可以 |

`ticket:read:all` 只扩大读取范围，不会变成外发权限。即使拥有 `ticket:read`，协作成员和观察员调用分享接口也会得到 `403`。

## 3. 外部访问者能看到什么

分享页位于 `/share/:token`，不要求 Cookie 会话或 API Token。它只读展示以下信息：

| 内容 | 是否展示 | 说明 |
| --- | --- | --- |
| 工单号、标题、状态、优先级 | 是 | 便于识别与跟进 |
| 类型、分类、机房、集群、产品序列号 | 是 | 支持 IDC 算力租赁场景定位问题 |
| 公开回复及作者显示名、时间 | 是 | 外部讨论所需的最小上下文 |
| 公开正文引用的内联图片 | 是 | 仅限该公开正文实际引用到的图片 |
| 内部备注 | 否 | 永远不会返回给分享接口 |
| 联系方式、邮箱 | 否 | 防止电话、邮箱等个人信息外泄 |
| 提单人、处理人、协作成员、队列 | 否 | 不暴露内部组织与人员信息 |
| 普通附件 | 否 | 不提供泛附件下载，避免误传内部材料 |
| 回复、编辑、状态流转、指派 | 否 | 分享页完全只读 |

> 内联图片的例外是有意设计：服务端只在“该图片的下载地址确实出现在一条公开回复正文中”时才放行。仅上传但未公开引用的图片、内部备注图片和普通附件均不能通过分享链接下载。

## 4. 安全设计

### 4.1 链接密钥与存储

创建时使用 `randomBytes(32)` 生成 256 位随机密钥，格式为 `shr_<base64url>`。数据库不保存原始密钥，只保存 SHA-256 哈希：

```text
浏览器拿到原始 token（仅一次）
        ↓ SHA-256
ticket_shares.token_hash（数据库）
```

因此，数据库备份、日志或普通后台列表被看到时，不能反向找回有效 URL。

### 4.2 生命周期

`ticket_shares` 的核心字段如下：

| 字段 | 用途 |
| --- | --- |
| `ticket_id` | 所属工单；工单删除时级联删除链接 |
| `created_by_id` | 创建人；用户删除时级联删除链接 |
| `label` | 管理端识别用途，不是密钥 |
| `token_hash` | 唯一 SHA-256 哈希 |
| `expires_at` | 到期时间；为空表示永不过期 |
| `revoked_at` | 撤销时间；非空即永久失效 |
| `created_at` | 创建审计时间 |

每次公开访问都会同时检查：密钥是否存在、是否已撤销、是否已过期。对外统一返回 `404`，不会暴露“链接曾经存在但已撤销”这类信息。

创建和撤销还会写入 `ticket_history`，字段为 `share_link`，方便在工单历史中追溯外发行为。

### 4.3 缓存、搜索与 Referer

分享 URL 是 bearer credential，任何拿到 URL 的人都能访问。因此公开接口及其内联图片响应均带：

```http
Cache-Control: private, no-store, max-age=0
Pragma: no-cache
X-Robots-Tag: noindex, nofollow, noarchive
Referrer-Policy: no-referrer
```

这会阻止浏览器共享缓存、搜索收录和跳转时向第三方泄露完整 URL。若前面接入 CDN，必须保持 `/api/shared-tickets/*` **不缓存**，也不要按 URL 把该路径转存到对象存储或边缘日志中。

### 4.4 使用责任

- 只将链接发送给确有必要的人员；不要粘贴到群公告、工单外的公开文档或截图中。
- 供应商或客户完成处理后应立即撤销，而不是仅依赖较长有效期。
- “永不过期”适合受控的长期审阅流程，不适合临时排障。
- 若误发链接，先撤销旧链接，再新建新链接；不能“修改”旧 URL。

## 5. 接口约定

基地址为 `/api`。前三个管理接口需要登录 Cookie 会话与 `ticket:read`，同时经过第 2 节的业务归属校验；个人 API Token 不适合管理分享链接。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/tickets/:ticketId/shares` | 取链接元数据，不含 token 或完整 URL |
| `POST` | `/tickets/:ticketId/shares` | 创建链接，响应仅本次含 `token` |
| `DELETE` | `/tickets/:ticketId/shares/:shareId` | 撤销链接 |
| `GET` | `/shared-tickets/:token` | 无需认证的只读内容 |
| `GET` | `/shared-tickets/:token/attachments/:attachmentId` | 公开正文内联图片的受控读取 |

创建请求示例：

```json
{
  "label": "供应商排障",
  "expiresInDays": 7
}
```

`label` 为可选字符串，最多 80 字符；`expiresInDays` 可为 1–365，省略表示永不过期。

响应中的 `token` 必须立即用于生成前端 URL：

```text
https://assay.cloudcele.com/share/<token>
```

完整字段和错误响应见 [04-API.md](04-API.md#34-工单分享链接)。

## 6. 代码实现定位

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 数据模型 | `apps/api/prisma/schema.prisma` | `TicketShare`、用户/工单关系 |
| 数据库迁移 | `apps/api/prisma/migrations/20260911090000_ticket_shares/migration.sql` | 创建表、索引与级联外键 |
| 服务层 | `apps/api/src/ticket-shares/ticket-shares.service.ts` | 密钥生成/哈希、权限、公开数据裁剪、图片控制 |
| 控制器 | `apps/api/src/ticket-shares/ticket-shares.controller.ts` | 管理接口、公开接口与安全响应头 |
| Web 管理面板 | `apps/web/src/components/TicketShareDialog.tsx` | 创建、复制、列出、撤销 |
| Web 公开页 | `apps/web/src/pages/PublicTicketSharePage.tsx` | 无需登录的只读展示 |
| 路由 | `apps/web/src/router.tsx` | `/share/:token` 公共路由 |

前端直接打开分享页时使用独立的 HTTP 客户端，避免普通业务 API 的 `401 → 登录页` 拦截器干扰已经失效的链接提示。

## 7. 部署与验证

### 7.1 数据库迁移

生产 API 容器启动时会执行：

```bash
prisma migrate deploy
```

本功能新增迁移 `20260911090000_ticket_shares`。手动部署时可先检查：

```bash
docker compose exec api ./node_modules/.bin/prisma migrate status
docker compose exec api ./node_modules/.bin/prisma migrate deploy
```

不要手工建表后跳过迁移记录；否则后续镜像的 `migrate deploy` 会认为数据库状态不一致。

### 7.2 冒烟检查

1. 登录为提单人或处理人，进入工单详情，确认“分享”按钮出现；
2. 创建一个 1 天有效的测试链接，复制后用无痕窗口打开；
3. 确认公开回复可见，而内部备注、邮箱和联系方式不可见；
4. 撤销该链接，刷新无痕窗口，应得到“链接无效或已失效”；
5. 检查工单历史，应看到创建/撤销分享链接的记录。

可用无效 token 做无需认证的基础探针：

```bash
curl -i https://assay.cloudcele.com/api/shared-tickets/shr_invalid
```

预期是 `404`，且 `Cache-Control` 同时包含 `private`、`no-store`、`max-age=0` 三个指令，并带有 `X-Robots-Tag: noindex, nofollow, noarchive`。有效链接的响应应为 `200` 且同样带这些头。

## 8. 当前边界与后续演进

当前版本重点是“安全地外部只读审阅”。如果未来需要外部人员参与处理，应新增**受控的外部协作身份**或单独的邀请制门户，而不要把匿名分享链接扩展成可写入口。

可独立评估的后续能力包括：

1. 密码保护的分享链接；
2. 最大访问次数与访问审计；
3. 指定邮箱收件人并验证后访问；
4. 对普通附件增加显式“允许随链接分享”的逐文件开关；
5. 分享链接到期前的提醒与批量撤销。

这些能力会引入额外的身份、审计和数据分类责任，应作为单独迭代设计，而不是默认扩大匿名链接权限。
